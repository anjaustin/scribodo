# Explicit Recall/Draft experiment — frozen DEV protocol

## Authorized scope

The author agreed to test division of labor: explicitly selected Recall and Draft
operations, without a classifier, new model, memory tier or production routing
change. This is the next experiment from `memory_causal_synth.md`, not a reversal
of the native no-go or permission to introduce automatic author-state authority.

## Before inference

Freeze `tests/fixtures/memory_native/operations-registration.json`, the generated
input, diagnostic C executable and source hashes before generation. Use the same
pinned local model, native SQL hydration/admission/streaming, effective 8,192-token
context, 1,024 reply tokens, temperature zero, repetition penalty 1.05, cache enabled
and 500 ms memory preparation limit. Keep all original candidate/reference/receipt
bounds. T1/T2 are off. Candidate discovery remains the diagnostic frozen eligible
SQL episode seam; no Qdrant or manuscript-wide selection claim.

Ten tasks × two recent-history layouts × two arms = 40 complete responses:

- Six original recall tasks: count, proposed color, rejected ferry, resume state,
  protected ambiguity and incomplete evidence.
- An accepted-color counterfactual changes only the final original author turn
  from nonacceptance to an explicit choice. This checks that Recall does not
  simply abstain on every proposed-choice question.
- Three draft tasks: current style override, coat-color-unspecified drafting,
  and drafting that preserves both accounts of the fire.

Both arms use episode presentation, identical SQL source identities/text within
each cohort, the same current request and decoding/resource settings. Generalist
uses the production creative persona. Specialized uses the preregistered operation
instruction. The operation is explicitly assigned by the authored fixture, never
inferred by a model. The diagnostic translation unit changes its own persona
pointer only between joined workers; no application behavior/API is changed.

Counterbalance arm order by conversation serial. Do not save generated replies
back into source history. Preserve both full immutable receipts and the compact
model-facing references. Verify all source IDs and current requests after fitting.

## Review and stop

Read all 40 complete responses. Score semantic fidelity, role/authority binding,
pending/protected distinction, current task, citation correctness and completion
separately from source admission. Novel imagery is permitted in Draft; silently
choosing the coat color, resolving the fire or presenting new details as prior
decisions is not. Requested two-sentence drafts must actually be two sentences.
Recall must not drift into new prose or reopen discarded choices.

All 20 specialized conditions must pass the small DEV screen before proposing an
opt-in production operation prototype. A pass would still need fresh held-out
acceptance and would not qualify T1/T2, default-on, broad privacy claims or an SLA.
If specialization fails, do not revise prompts against this fixture until green;
report the limit and leave production unchanged. No claim that a system-prompt
intervention isolates a unique neural mechanism: its wording and length change.

## Completed result

Run `build/mo-nvvlimc8` completed all 40 responses with Sources, matching original
IDs within cohorts, intact current requests, and no errors or truncations. Every
response was reviewed; the specialized arm failed the frozen screen. Common-task
specialized results: 11 pass, 6 fail, 3 uncertain. Including its own additional
draft-only operation contract: 9 pass, 8 fail, 3 uncertain. Do not implement the
production prototype or retune this fixture. See
`../docs/MEMORY-013-explicit-operations-dev.md` and
`memory_operation_review.json` for per-condition evidence, fair baseline contract
distinctions, gains, failures and uncertainty.

Post-run harness hardening: empty/malformed prepared requests now count as failed
mechanical preservation checks instead of raising a JSON/index exception while
building the report. Valid-request output is unchanged; the frozen run retains
its original copied wrapper/hash. This does not change prompts, inference or
rescore the completed experiment.
