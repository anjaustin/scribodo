## What is actually retained, and which representation is authoritative?

### Takeaway

This is a hierarchy of externally retained conversation data and compact model-facing views, not an enlarged transformer context. Distinguish the client's transcript, the proxy's durable transcript/state, summaries, replay caches, and indexes; their completeness and lifetimes differ.

### Cited Findings

- **Source-verified — client transcript versus proxy view:** the proxy stores fold state so a client can resend a huge raw transcript after restart and still send a small folded view upstream. The client's history is not thereby shortened. `guardedBuild()` explicitly supplies the **raw tail** to unified ingest while the JSON envelope retains a bounded folded view; a resident tail already marked folded must not masquerade as a complete raw log. [persist.ts L48–100](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/persist.ts#L48-L100), [L2763–2804](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/persist.ts#L2763-L2804).
- **Source-verified — persistent transcript and view pointers:** unified `messages` is a first-seen sequence log, keyed by `(session_id, seq)` and unique `(session_id, msg_id, content_hash)`. `tail_json` stores pointer sequences for `lastMessages`/`pluginSnapshot`, not another copy of their content; these can be subsequences with interior holes, not just a suffix. `content(hash, byte_len, refcount, algo, bytes)` is SHA-256-addressed storage. [schema.ts L123–188](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/storage/schema.ts#L123-L188), [ingest.ts L1–26](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/storage/ingest.ts#L1-L26).
- **Source-verified — authoritative ledger versus summary and cached originals:** `CompressionState.blocks` carries `CompressionBlock` payloads and active/inactive status; a summary is the lossy model-facing representation, not the original. `Session.blockContents` maps block IDs to `{one, full}` rendered text/count caches: `one` means direct messages plus child summaries, `full` means original-message rendering; identical views deduplicate by storing `one:null`. Capture occurs when compression lands, while source messages are available. These are text renderings, **not necessarily original wire JSON or every multimodal byte**. [session.ts L17–39](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/session.ts#L17-L39), [stream.ts L1297–1333](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/stream.ts#L1297-L1333).
- **Source-verified — misleading SQL column naming:** `blocks.payload_json` carries the actual block including its summary. In the replay cache leg, `blocks.summary_hash` references serialized **full BlockView**, while `one_hash` references the one-level view. `getBlockContents()` parses `b.summary` into `full`; do not interpret every column named `summary` as only an LLM summary. [ingest.ts L19–24](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/storage/ingest.ts#L19-L24), [store.ts L2733–2775](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/storage/store.ts#L2733-L2775).
- **Source-verified — identities are not interchangeable:** raw/core message IDs identify message instances; `mNNNNN` refs are model-addressable aliases in `messageRefs.byRaw/byRef`; `bN` identifies a compression block within a session. Unified row `seq` is server arrival order. SHA-256 content hashes identify serialized content bodies, not a semantic concept or independent evidence that two occurrences are the same message. In CCR, `StoredEntry.hash` instead hashes the stored original **text**, and a frozen `rawId` records which message supplied it. [schema.ts L156–188](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/storage/schema.ts#L156-L188), [content-store.ts L29–55, L72–99](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/content-store.ts#L29-L99).
- **Source-verified — CCR store is separate:** `MessageContentStore={version:1, byHash, byRef}` stores deduplicated original text and per-ref metadata (kind/tool, token/character count, 96-character default head, optional command). First insertion for a ref wins; repeat content shares `byHash`. It is outside `CompressionState`, persisted through a content-store companion and a unified mirror. [content-store.ts L3–26, L29–117](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/content-store.ts#L3-L117), [store.ts L114–127](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/store.ts#L114-L127).
- **Source-verified — defaults:** persistence is enabled unless explicitly disabled; unified storage defaults to **full**, backend defaults to **SQLite**, and JSON envelope writing remains **on** by default. `legacy` means JSON authoritative, `shadow` adds reconciled unified ingestion, `full` enables unified-first reads with compatibility fallback. SQLite-only `storage.jsonWriter=off` makes the database the sole persistent copy. AES-256-GCM envelope encryption explicitly disables the cleartext unified sidecar; zstd is opt-in, plaintext JSON the default. Default data root is `~/.local/share/billion-context/sessions/` (XDG/env overrides), with `index.db` in that directory. [knobs.ts L841–897](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/knobs.ts#L841-L897), [backend.ts L398–404](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/storage/backend.ts#L398-L404), [persist.ts L528–584](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/persist.ts#L528-L584), [paths.ts L4–47](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/paths.ts#L4-L47).
- **Source-verified — other backend:** MySQL 8.0 via lazily loaded `mysql2/promise` implements the async operation-level contract, preserving backend-specific transactions. It is not merely a README proposal. Synchronous reads use JSON envelopes for this backend; writer-off is SQLite-only. An obsolete comment says MySQL does not open, contradicted by `openBackend()`'s implementation immediately below it. [backend.ts L6–24, L337–374, L407–414](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/storage/backend.ts#L337-L414), [persist.ts L580–609](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/persist.ts#L580-L609).

### Inferences

- **Source-based inference:** “original archive” is shorthand, not one universal object. A durable unified transcript, block-render caches, a CCR text store, legacy envelopes, and the cold archive JSONL can coexist. An application must specify which of these it backs up and which retrieval APIs reach it; a summary or a bounded JSON tail alone is not a complete transcript backup. [persist.ts L2787–2803](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/persist.ts#L2787-L2803), [store.ts L1877–1914](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/storage/store.ts#L1877-L1914).

### Gaps

- This pass does not enumerate every client's local transcript format or prove identical archival completeness across every plugin/proxy mode. Do not generalize the proxy capture path into an all-client/all-modality raw-byte preservation guarantee; the concrete path and retained source must be named. [stream.ts L1322–1328](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/stream.ts#L1322-L1328).

## How do search, decompression, CCR, and rare-fact recovery work?

### Takeaway

The exposed `search_context` is **case-insensitive literal keyword search**, not semantic retrieval. It can find a fact omitted from summaries by scanning retained folded originals, but only where those originals are reachable; nothing guarantees the model will decide to search or choose matching words.

### Cited Findings

- **Source-verified — exact search semantics:** `executeSearchContext()` uses `blockDocs(state)` over **all active and inactive blocks**, text=`topic + summary`, then explicitly selects `algorithm:"substring", minScore:1e-9`. Terms are lowercased and whitespace-split; score sums literal occurrence counts for each term (OR-like positive match, not all-terms-required, no stemming/typo tolerance). Default limit is 5 summary hits. This proxy function does **not** use the kernel's available async semantic/embedding API or its default hybrid scorer. Optional plan-awareness only reranks already lexically matched own-session summary candidates using current plan terms. [decompress-shared.ts L821–863](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/decompress-shared.ts#L821-L863), [substring.ts L4–32](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/search/algorithms/substring.ts#L4-L32), [search/index.ts L1–32](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/search/index.ts#L1-L32).
- **Source-verified — originals corpus:** when backed by a `Session`, `originalTextsOf()` iterates `session.blockContents`, searches each `full.text` after stripping ACP tag chrome, and adds up to `limit` original-text hits not already in the summary results. Hits include owning block IDs, snippets and ref spans where available. The block must still exist in `state.blocks`; orphan cache entries without a state block are filtered. Provider exceptions are swallowed, degrading to summary-only search. Neither visible messages nor every row in the raw transcript/CCR store is automatically searched. [decompress-shared.ts L791–818, L864–938](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/decompress-shared.ts#L791-L938).
- **Source-verified — scope/lineage:** default is current session; an explicitly supplied `conversation_id` can select a historical session read-only, but that argument is deliberately **not advertised in the tool schema**. Foreign **resident** sessions can contribute original-text caches; **disk-only** foreign sessions resolve only `CompressionState`, so originals are not searched. Cross-session block IDs cannot be directly fed to current-session decompress; tool recommends `bili export <session> [--full]`. Derived children have a cycle-guarded ancestor walk capped at 8; search fallback first requires a **summary** lexical match in an ancestor, so an ancestor original-only match can be missed before its originals provider is ever called. [decompress-shared.ts L489–509, L941–995](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/decompress-shared.ts#L941-L995), [cross-session tests L64–115](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/tests/search-context-cross-session.test.ts#L64-L115).
- **Source-verified — `decompress`:** this is copy/retrieval, not a permanent unrolling of the compressed context. The block stays active and future forwarded views remain folded. Default returns cached `one` (one level of nested content); `full:true` selects `full`. Cache miss calls `collectBlockContent()` on available messages and ultimately falls back to **the summary** if no text was collected. Whole-block inline restore can set a `restoredInline` flag for refolding; IDs/refs do not move. Explicit `toFile` avoids a large inline payload. Native-compaction-archived blocks are explicitly refused even if cited by an old summary. [decompress-shared.ts L147–162, L191–247](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/decompress-shared.ts#L147-L247).
- **Source-verified — range restoration:** `decompress({blockId,startId,endId})` requires **CCR enabled**, both valid ascending message refs, and per-message coverage. It selects covered refs inside the interval, prefers a CCR entry only when `entry.rawId` matches that covered message, then falls back to current source-view text. Missing messages can be skipped; it fails if no parts survive. This is not an unconditional exact raw-message replay. Returned text can be file-delivered or queued as an ephemeral request-only injection. [decompress-shared.ts L379–480](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/decompress-shared.ts#L379-L480).
- **Source-verified — `acp_retrieve`/CCR:** CCR defaults **off**. Arrival-time CCR stores eligible tool-result **text** at >=4,000 estimated tokens, excluding protected, configured-excluded and ACP tools; substitutes a deterministic placeholder carrying ref, kind, size, head and command. When enabled, proxy fold-time storage also captures covered text while available, skipping reasoning and canonical placeholders. `acp_retrieve({ref})` is exact key lookup `byRef → hash → byHash`, not search. Ref not found or body absent means not-found. Originals >=4,000 tokens are exported if an export directory is supplied; smaller originals are returned in an untrusted-data-framed **tool result**, not a synthetic high-trust message. [ccr.ts L24–62, L395–433, L454–558, L606–658](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/ccr.ts#L395-L433), [content-store.ts L102–117](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/content-store.ts#L102-L117).
- **Source-verified — host delivery/failure details:** `executeRetrieve()` writes exports under `<stateDir>/retrieve/<ref>.txt` with mode 0600. A failed file write returns failure plus bounded head preview instead of a dead file pointer. Effective CCR gates matter: plugin-mode CCR is supported only for Anthropic/OpenAI wire paths. Resetting a session's compression resets the CCR store because refs restart; a retained old ref is not a global permanent address across generations. [store.ts L101–127, L199–245](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/store.ts#L199-L245), [session.ts L1661–1677](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/session.ts#L1661-L1677).
- **Test expectations, not executed:** tests explicitly cover inactive-block search, unique keyword present only in originals, and originals-provider failure degrading to summary-only results. Cold cross-session search asserts file bytes remain unchanged and no save is scheduled. [search-context.test.ts L105–155](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/tests/search-context.test.ts#L105-L155), [cross-session tests L187–218](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/tests/search-context-cross-session.test.ts#L187-L218).

### Inferences

- **Worked persistence/restore example (illustrative, not executed):** user says “The recovery phrase for staging is **cobalt heron 17**” in message `m00042`. A later fold `b7` summarizes only “Discussed staging recovery.” If capture retained that message in `b7.full`, a subsequent prompt mentioning “staging recovery phrase” gives the model a reason to invoke `search_context({query:"staging recovery"})`; that can locate `b7` via summary or original text. `decompress({blockId:"b7",full:true})` reads the rendered original cache, including the phrase. With fold-time CCR available, `acp_retrieve({ref:"m00042"})` can return stored original text directly instead. After a settled save and proxy restart, state and lazy originals can reload from the unified store/companions. This sequence depends on retaining the source and knowing an applicable lexical cue; it is not reconstruction from the lossy summary. [stream.ts L1297–1333](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/stream.ts#L1297-L1333), [decompress-shared.ts L219–235, L791–895](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/decompress-shared.ts#L791-L895), [store.ts L114–127](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/store.ts#L114-L127).
- **Irreducible recall failures:** tools are advertised as available and the prompt says search before decompressing, but no code here detects every omitted fact and forces a correct search. With no clue that a relevant forgotten detail exists, the model may confidently answer without searching. With a clue but no shared substring (synonyms, paraphrase, typos), lexical recall can fail. High-occurrence generic words can rank the right block below the limit. A cold foreign session or ancestor original-only match can fail for scope reasons despite retained bytes. Missing/corrupt/pruned originals, pre-CCR folds, or generation resets add storage/addressability failures. Thus **storage reversibility ≠ guaranteed behavioral recall**. [compress-tools.ts L204–208](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress-tools.ts#L204-L208), [substring.ts](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/search/algorithms/substring.ts), [decompress-shared.ts L969–994](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/decompress-shared.ts#L969-L994).
- **“Reversible” must be conditional:** full block restoration can be faithful to retained rendered text; CCR can return exact stored text. Neither means every mode retained every input byte forever. CCR deliberately excludes reasoning; placeholder-without-source is refused rather than stored as a fake original; fallback decompress can return only a summary; native compaction can render old blocks unavailable; retired-message media references are released. [ccr.ts L626–643](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/ccr.ts#L626-L643), [decompress-shared.ts L198–235](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/decompress-shared.ts#L198-L235), [store.ts L942–967](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/storage/store.ts#L942-L967).

### Gaps

- No automatic semantic rare-fact recall guarantee or global cross-session raw-archive search endpoint was established in this inspection. The verified model tool searches named block corpora; the cold archive restore reader scans JSONL for a session ID, which is not full-text archive retrieval. ## What bounds resources, survives restart, and remains prunable?

### Takeaway

The code bounds warm session caches and sheds large idle fields, but does not make all costs constant in archive size. Full-resend hosts, live fold/ref state, broad original-text scans, full cache rematerialization, and cold-archive restore retain important history-dependent costs.

### Cited Findings

- **Source-verified — transaction and durability:** unified ingestion is one write transaction; SQLite uses WAL, `synchronous=NORMAL`, 5-second busy timeout, foreign keys, 8 MiB journal-size target, and incremental auto-vacuum. Write drivers use `BEGIN IMMEDIATE` (nested savepoints), reads deferred snapshots. JSON saves use temporary-file + rename, per-ID serialization and default **500 ms debounce**; documentation explicitly says **no file/directory fsync**, so process-crash safety is only up to the last successful write, not power-loss durability. Sidecar originals are saved before the session write (`writeNow` throws if originals cannot be saved). JSON, CCR companion, DB and archive file are not shown as one cross-file atomic transaction. [schema.ts L88–115](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/storage/schema.ts#L88-L115), [driver.ts L108–120, L152–183](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/storage/driver.ts#L152-L183), [persist.ts L60–98, L3189–3226](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/persist.ts#L3189-L3226), [knobs.ts L376–385](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/knobs.ts#L376-L385).
- **Source-verified — incremental ingestion, not universally O(delta) turns:** a trusted watermark permits only new messages to be serialized/inserted after verifying the boundary `(seq,msgId,contentHash)` **inside** the transaction; rejects conflicting or repeated identities and falls back to full planning on disagreement. Tests expect boundary+new-message serialization, metadata-only one-boundary serialization, and snapshot-bearing sessions to stay full-path. These tests describe ingestion subwork, not all parsing/rendering/persistence work. [store.ts L823–843](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/storage/store.ts#L823-L843), [watermark tests L117–180, L509–525](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/tests/storage-ingest-watermark.test.ts#L117-L180).
- **Source-verified — residency defaults:** max **256 sessions**, boot warm count **0**, optional warm decoded budget **64 MiB**, pooled estimated resident budget **512 MiB**. A per-session “hard” setting defaults to the pooled budget, but its enforcement drops only droppable fields; code explicitly says hot `state` and transient remainder are not droppable. It is **not a hard process-RSS ceiling**. In-flight sessions cannot be safely evicted, failed saves veto eviction, and count exhaustion can throw. [knobs.ts L402–457](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/knobs.ts#L402-L457), [persist.ts L3100–3135](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/persist.ts#L3100-L3135), [session.ts L1303–1318, L2045–2083](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/session.ts#L2045-L2083).
- **Source-verified — active windows/lazy reads:** persisted folded tail defaults to **16,384 tokens**, keeps newest whole messages, with at least one message even if oversized; zero disables this tail but not summaries/original block caches. After successful settled saves, idle raw tails fold to that view; metadata, block contents and CCR can become lazy proxies. Spill requires no in-flight request, successful landing proof, and matching durable/live revision. `LazyBlockContents.get()` rematerializes the **entire map**, not only the requested block, and throws if missing storage would otherwise silently erase content. Ordinary loads read only pointer message rows and paged block material; paging bounds per-query batches, not final live block/ref state. [persist.ts L4061–4090, L3286–3297](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/persist.ts#L4061-L4090), [session.ts L31–82](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/session.ts#L31-L82), [bounded-load tests L78–109](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/tests/storage-bounded-load.test.ts#L78-L109).
- **Source-verified — derived search features bounded but not a vector database:** module-global `docFeatures` LRU defaults to **8×1024×1024 source characters**, not a strict byte/RSS cap. It caches lowercased text, term frequencies and bigrams, although proxy search selects substring scoring. Source comments warn full-corpus scans exceeding capacity can retokenize repeatedly; feature footprint depends strongly on distinct tokens/bigrams. This is a derived cache, not the durable archive. [doc-cache.ts L1–38, L43–85](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/search/doc-cache.ts#L1-L85).
- **Source-verified — what survives/remains retained:** complete raw-log ingestion retires absent historical **text** rows instead of deleting them; retired rows retain content refs and are excluded from default replay. **Media** mappings are released on retirement. CCR entries are append-only per generation but a full reset clears the store. Therefore even “append-only facts” comments need qualification. ### Inferences

- **Complexity, inferred from source, not timed here:** normal folded model input can remain small relative to transcript, and idle residency avoids retaining all original bytes across all sessions. But state blocks/ref ledgers and per-turn reconciliation need not be constant-size; an originals search builds/scans all retained block texts, substring counting scans text for each term, and `LazyBlockContents` loads an entire session map. Nested full caches can duplicate rendered originals across tiers despite CAS deduplication of identical bodies. Cold archive restore is O(total JSONL archive bytes) memory/read work because it reads/splits/re-writes the entire log. No source-backed O(1) whole-system cost follows from a bounded prompt window. [decompress-shared.ts L810–895](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/decompress-shared.ts#L810-L895), [substring.ts L14–32](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/search/algorithms/substring.ts#L14-L32), [session.ts L31–78](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/session.ts#L31-L78), [store.ts L1963–2038](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/storage/store.ts#L1963-L2038).
- **Host boundary:** even perfect proxy-side incremental ingestion cannot undo work the host has already done building/serializing/uploading a full transcript or retaining it in UI/database caches. Effectively unlimited sessions require host cooperation (stable IDs, incremental transport/server-owned history, host-side paging/compaction or migration), not only small outbound LLM prompts. The existing incident is consistent with this separation, but its timings should remain labeled a report. [persist.ts L2787–2803](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/persist.ts#L2787-L2803), [Issue #5796](https://github.com/ranxianglei/billion-context/issues/5796).
- **Responsible “effectively unlimited memory” requirements:** (1) durable, backed-up, tenant-scoped original log and explicit retention/deletion semantics; (2) compact active views with stable lineage/addressing; (3) on-demand exact-source retrieval independent of lossy summaries; (4) scalable indexed original-text retrieval across cold sessions, with honest scope and degraded-search indicators; (5) query/recall policy that actively checks prior evidence and admits uncertainty, ideally evaluated on rare facts; (6) host-side history bounds and incremental requests; (7) disk quotas, admission/concurrency controls, crash/power-loss testing and restore drills. The inspected system provides parts of 1–3 and cache resource controls, but its summary-only cold-session path, non-semantic exposed search, full map loads and durability windows mean the stronger product promise needs qualification/work. This is an engineering inference, not an upstream guarantee.
