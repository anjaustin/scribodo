## 1. What happens between the agent's request and its eventual answer?

### Takeaway

In ordinary proxy mode, bili does more than shorten a request: it supplies context-management instructions and tool schemas, intercepts those tool calls, executes them, reconstructs a smaller conversation, and makes continuation requests itself. In plugin mode the native host owns that tool loop, while bili still owns compression state and the outbound folded view. ([relay.ts, lines 1741–1749](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/server/relay.ts#L1741-L1749); [loop/core.ts, lines 1255–1308](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/loop/core.ts#L1255-L1308); [plugin.ts, lines 92–106](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/plugin.ts#L92-L106))

#### Prompts and refs the model sees

- The standing prompt combines compression philosophy, summary-writing rules, tag/marker integrity instructions, attribution, and optional dialect/feature notes. The canonical prompt objects distinguish tier-1 summary rules from tier-2 distillation and tier-3 condensation. In external-summary mode the conversation-side summary-writing section is removed and replaced by a disclosure: the model selects consumed ranges, while a separately configured service writes the summary. ([prepare-openai.ts, lines 417–440](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/server/prepare-openai.ts#L417-L440); [kernel/prompts.ts, lines 22–46](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/prompts.ts#L22-L46); [external-summary-surface.ts, lines 6–26](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/external-summary-surface.ts#L6-L26))
- `processTurn` renders refs (`renderTags: "text-only"` normally; optional `none`), the nudge supplies live compressible ranges, and `acp_status` is a recovery surface for current refs. Refs are not safe to invent as a contiguous integer interval: the error handling explicitly calls the space sparse and directs the model to current status rather than numeric probing. ([prepare-openai.ts, lines 88–91 and 290–319](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/server/prepare-openai.ts#L88-L91); [kernel/compress.ts, lines 586–601](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L586-L601))

#### Plugin mode is a different ownership contract

- A native integration fetches `GET /__bili/plugin/manifest`, registers tool schemas in its host, stamps plugin/conversation headers on requests, and executes ACP tools through `POST /__bili/plugin/tool`. The endpoint calls the same `executeProxyToolAsync` under a session lock. Model-emitted native compress calls must reach the host; the proxy does not swallow them into its own loop. ([plugin.ts, lines 92–106](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/plugin.ts#L92-L106); [lines 2216–2249](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/plugin.ts#L2216-L2249); [relay.ts, lines 1741–1749](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/server/relay.ts#L1741-L1749))
- **Do not repeat the stale blanket claim “plugin mode suppresses nudges.”** Current preparation explicitly injects trailing nudges in **both modes**, conditional on reachability/self-heal/auto-fold gates; plugins supply native tools, but the proxy supplies proactive nudges. DSH's reachability gate can suppress the compress surface where the host has not actually exposed it. A separate plugin-compression override can request the proxy wire channel while preserving plugin identity, for hosts whose native toolsets are deferred. ([prepare-openai.ts, lines 101–111 and 442–447](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/server/prepare-openai.ts#L101-L111); [nudge gates, lines 341–361](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/server/prepare-openai.ts#L341-L361); [plugin.ts, lines 118–126](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/plugin.ts#L118-L126))
- Summary carrier differs: a native model-written summary can survive in the host's persisted compress call. In plain proxy mode the call is ephemeral, and preflight has no original model tool call, so the anchored `acp_summary` must survive. `stripKernelSummaries` removes only redundant carriers; treating every kernel summary as redundant loses proxy-mode memory. External-generated summaries also cannot rely on the model's non-authoritative hint as their carrier. ([server.ts, lines 2306–2324](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/server.ts#L2306-L2324); [external-summary-compress.ts, lines 126–148](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/external-summary-compress.ts#L126-L148))

## 2. Who chooses ranges and writes summaries, and what actually triggers extra calls?

### Takeaway

Default proactive compression asks the conversation model to choose ranges **and write summaries in its tool arguments**; there is no always-on independent summarizer. Preflight instead chooses ranges programmatically and spends dedicated summary requests, even when it uses the same model/provider; the external summary service, auto-folding, and model-decided nudge timing are separate opt-in features. ([external-summary-compress.ts, lines 38–50](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/external-summary-compress.ts#L38-L50); [preflight.ts, lines 1283–1319](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/preflight.ts#L1283-L1319); [external-summary-surface.ts, lines 68–77](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/external-summary-surface.ts#L68-L77))

### Cited Findings

#### Actual defaults, units, and soft versus hard paths

- Default tool/nudge injection is **on**. Kernel defaults: `growthFloor = growthCap = 50000`; pressure at **75%**, emergency at **95%**, truncation at **95%**; preserve **3 recent messages** and **5000 recent tokens**; minimum compress range **5000 characters**, summary **50–20000 characters**. The range unit is characters, despite the surrounding token-oriented configuration. CCR, absorb, and crush are off. Tiering is enabled, with count triggers 1000/2000, not “distill every five blocks” (the separately present `promotionThreshold: 5` is not the same field). ([config.ts, lines 1731–1736](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/config.ts#L1731-L1736); [kernel/config.ts, lines 7–56](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/config.ts#L7-L56); [compress-settings.ts, lines 254–258](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/compress-settings.ts#L254-L258))
- **“Every 50K” is shorthand, not an exact periodic scheduler.** `resolveAdaptiveGrowth` clamps to 50K at every window by default. However actual growth eligibility uses `max(20000, .45 × 50000) = 22500` tokens since the reference, plus tier ready-mass thresholds (T1 50K; T2/T3 normally 75K). First-sight backlog can bypass growth at ≥45% usage with ≥50K ready mass. At ≥75% pressure, growth/cadence are bypassed, but the chosen tier must offer at least `max(5000, 1% × window)` reclaimable tokens. There are also suppression/breaker/reachability gates outside the kernel. Therefore neither “50K of new text always triggers” nor “nothing happens until 75%” accurately describes this snapshot. ([kernel/compress.ts, lines 1978–2013](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L1978-L2013); [lines 2048–2114](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L2048-L2114); [lines 2131–2148](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L2131-L2148); [lines 2195–2233](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L2195-L2233); [prepare gates](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/server/prepare-openai.ts#L341-L361))
- A **soft nudge is an instruction**, not forced summary execution: it goes to the conversation model, which may call compress or ignore it. Emergency nudging and kernel truncation are separate from **preflight**, which runs before forwarding when the payload reaches its effective target and can itself compress. Preflight takes the effective input window, and a lower session-local overflow wall can supersede ordinary headroom. ([prepare-openai.ts, lines 448–505](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/server/prepare-openai.ts#L448-L505); [server.ts, lines 3736–3806](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/server.ts#L3736-L3806))

#### Estimation and window/headroom are orchestration inputs, not exact tokenizer knowledge

- The generic fallback window is **200000**, but request-specific configuration/host/runtime/model evidence can resolve another window. For unknown local models this is not discovery of their true limit; configure the actual window rather than trusting the anonymous default. ([config.ts, line 1640](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/config.ts#L1640); [handle.ts window-source diagnostics, lines 2488–2502](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/server/handle.ts#L2488-L2502))
- `defaultCountTokens` counts CJK characters approximately 1:1 and other characters at `ceil(chars/4)`; `estimateCoreMessages` also includes projected thinking mass. A separate upper estimator counts **one token per character**, and a byte estimator supports “doomed probe” protection. These are heuristics, not the backend's tokenizer. A usage-grade, current-route anchor takes precedence where valid; stale or implausible anchors are rejected, and preflight has route-calibrated estimates plus explicit usage/overflow provenance. ([kernel/tokenize.ts, lines 5–12 and 30–40](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/tokenize.ts#L5-L40); [preflight.ts, lines 411–430 and 470–491](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/preflight.ts#L411-L491); [server.ts, lines 2883–2955](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/server.ts#L2883-L2955); [preflight gate, lines 3862–3912](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/server.ts#L3862-L3912))

## 3. How does the orchestration preserve cache prefixes, and what integration assumptions remain?

### Takeaway

Bili tries to make ordinary growth append-stable and to keep a fold's new representation identical between internal continuation and the next client replay. A fold still rewrites the request from its earliest changed anchor, and local inference savings depend on the backend actually reusing appropriate state—not on a remote provider's cached-input billing discount. ([cache-friendly-proxy.test.ts, lines 128–158](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/tests/cache-friendly-proxy.test.ts#L128-L158); [prepare-openai.ts, lines 411–416](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/server/prepare-openai.ts#L411-L416))

### Cited Findings

- **Static head, volatile tail:** static instructions stay in the system prefix, changing nudges are appended at the tail. The four ACP schemas are injected consistently rather than appearing only when pressure is high. The title-generation exception avoids converting small auxiliary calls into compression turns. This design preserves the possibility of an upstream longest-prefix cache hit; it does not command a cache implementation into existence. ([prepare-openai.ts, lines 93–102](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/server/prepare-openai.ts#L93-L102); [lines 411–447](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/server/prepare-openai.ts#L411-L447))
- **A fold is an unavoidable invalidation from the changed anchor onward**, not a promise that all past work stays cached. Tests specifically assert that bytes before the summary anchor do not change, and the new summary persists byte-identically through the next ordinary turn. `refreshFolded` mirrors steady preparation; its comments document prior failures caused by adding/removing summary carriers, changing separators, reordering instructions, and keeping ephemeral loop frames. The proxy must render the same history twice in the same way. ([tests/cache-friendly-proxy.test.ts, lines 136–158](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/tests/cache-friendly-proxy.test.ts#L136-L158); [relay.ts, lines 2136–2174 and 2202–2226](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/server/relay.ts#L2136-L2226))
- **Incremental folding is not always monotonic append.** Disjoint later summaries can coexist; a superset fold can replace an earlier summary, and tier distillation rewrites older summary mass. The regression suite explicitly tests superset swallowing, partial overlap coexistence, and later tail folds retaining unrelated earlier summaries. Thus folding earlier material or merging summaries can move the cache-loss point backward. ([tests/cache-friendly-proxy.test.ts, lines 539–582](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/tests/cache-friendly-proxy.test.ts#L539-L582); [kernel/compress.ts, lines 2188–2194](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L2188-L2194))
- **Fold-point relocation is an experimental option, not the baseline:** `compressAtFoldPoint` can relocate surviving tool-call carriers to their fold points, with a second switch to clear droppable thinking. The relay mirrors it on internal rounds, and signed/strict-thinking must not be casually rewritten. Do not confuse this switch with the normal proxy-mode anchored `acp_summary`, which exists without relocation. ([compress-settings.ts, lines 332–336](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/compress-settings.ts#L332-L336); [config.ts, lines 631–645](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/config.ts#L631-L645); [relay.ts, lines 2202–2219](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/server/relay.ts#L2202-L2219))
- **Source replay stability is necessary but not sufficient for a cache hit.** The loop's cache ledger tracks route origin, credential fingerprint, and generation-parameter fingerprint, and explicitly notes that model effort/thinking changes can repartition the provider cache namespace. It records missing cache reports as unknown, not a factual zero-hit measurement. OpenAI-compatible non-OpenAI hosts have `prompt_cache_retention` removed; bili-owned `prompt_cache_key` stamping is **disabled by default** at this snapshot, while genuine client keys can pass through. - **Inspected cache regressions measure representation, not GPU time or bills.** `cache-friendly-proxy` captures mock-upstream requests for all four wires, requires at least two folds, verifies plain-growth prefix equality allowing trailing volatile slots, stable pre-fold head, and persistence through the post-fold next turn. - **Billing savings versus computation:** a provider's discounted cached-input tokens are a pricing fact; the code's observed `cachedTokens` and ledger cannot prove proportional reduction in compute. The net result depends on backend reuse and workload, and cannot be read off a “tokens saved” counter alone. This is an inference from the explicit separate usage/continuation accounting and representation tests, not an empirical benchmark claim. ([core.ts, lines 441–470](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/loop/core.ts#L441-L470); [cache fold-transition assertions](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/tests/cache-friendly-proxy.test.ts#L136-L158))
- **For local LFM3 specifically, do not import remote-provider discount/cache-hit claims.** The inspected orchestration sends reconstructed API bodies and side calls; it does not establish how an LFM3 server checkpoints, keys, branches or invalidates its recurrent/other inference state. Benefits must be measured with the actual server implementation, including fold-time reprocessing and summary inference, not assumed from OpenAI/Anthropic billing fields. ### Gaps

- This research did not inspect an LFM3 inference backend, establish its exact state-reuse semantics, measure live provider caching, or quantify net dollars/joules/latency. No such number should be inferred from the source regression suite.

#### Important integration assumptions a naive “just put a proxy in front” proposal misses

1. **Stable session and history identity are part of the API contract**, not merely an endpoint URL. bili reconciles replayed history and stores fold state; client-native compaction, edits, tool-ID rewrites or system drift can change that representation. Preparation includes explicit reconciliation/native-compaction handling before it can safely fold. ([prepare-openai.ts, lines 199–285](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/server/prepare-openai.ts#L199-L285))
2. **Pick the ownership mode deliberately.** Plain proxy core tools are executed internally; plugin hosts must register tools, preserve their call/result pairing, call the tool endpoint, and run their native continuation loop. Model-visible tool reachability must actually exist; plugin headers alone do not make a deferred/hidden tool callable. ([plugin contract](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/plugin.ts#L92-L126); [prepare reachability](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/server/prepare-openai.ts#L101-L111))
3. **The model must tolerate the injected instructions/refs and be able to emit correct compression arguments.** Defaults rely on its judgment and summary-writing; external summary removes authorship from the main model, but not range selection unless auto-fold/preflight is doing the selection. Failure/loop caps can end a turn without finishing the user's objective. ([external-mode disclosure](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/external-summary-surface.ts#L6-L26); [loop bounds](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/loop/core.ts#L1555-L1609))
4. **Backend tokenizer, context/output walls and usage reporting need validation.** The 200K generic fallback, character heuristic, 25%-capped headroom and usage learning are not knowledge of a custom local model. A model can reject before it sees a nudge, making preflight and recognized overflow recovery essential. ([fallback](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/config.ts#L1640); [estimator](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/tokenize.ts#L5-L12); [headroom](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/util.ts#L565-L600))
5. **Timeout/cancellation/error handling must allow multi-call turns and in-band failure.** Proxy calls can spend time summarizing before a main completion; after the hold grace, HTTP 200 can carry an eventual error. A host cannot regard every completed HTTP stream as successful task completion. ([hold/error handling](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/server/handle.ts#L2880-L2917); [fresh per-batch deadlines](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/external-summary-runtime.ts#L70-L79))
6. **External summaries change the data boundary.** Selected source text plus read-only current-context/other-summary reference material is sent to separate configured targets, with their credentials and fallback order. That is an explicit deployment/privacy choice, not an implementation detail of the default same-model path. ([external-summary-compress.ts, lines 96–119](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/external-summary-compress.ts#L96-L119); [target credentials](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/external-summary-runtime.ts#L32-L52))
7. **File-based retrieval assumes locality or shared storage.** A proxy-local CCR/decompress export pointer is useful only if the agent's read tool can access that filesystem path; a remote proxy cannot assume the host can read its files. Large CCR retrieves normally use exactly such pointers. ([store.ts export path/write](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/store.ts#L215-L244); [kernel threshold/pointer](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/ccr.ts#L403-L433))
8. **Cache benefit must be demonstrated on the chosen backend, and optional tools need wire-level tests.** A byte-stable prefix is useful preparation, not proof of LFM3 state reuse or savings. The core four's stream interception is explicitly implemented; the optional CCR classification mismatch above is reason to test the complete host→proxy→model→host loop rather than assuming every injected tool is transparent. ([prefix assertions](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/tests/cache-friendly-proxy.test.ts#L128-L158); [OpenAI classification](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/src/loop/adapter-openai.ts#L376-L435))
