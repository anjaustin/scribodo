# Compression-kernel algorithms at c3dfbe6b21a1b2fc3642594043bc81fd2ae91247

## 1. What is the real memory representation, and how does a fold change it?

### Takeaway
This is a model-authored, explicitly indexed hierarchy of replacement summaries, not an enlarged transformer context window, not ZIP, and not one rolling summary. The kernel maintains coverage and representation bookkeeping; semantic fidelity remains the responsibility of the externally supplied summary. [Source](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L1702-L1880)

**Source-verified core types.**

- `CoreMessage` carries `id`, role (`user|assistant|system|tool`), content type (`text|tool-call|tool-result|reasoning`), optional text, tool name/call ID, invisible-but-metered `thinkingTokens`, host checkpoint marker `summaryOfBlockId`, optional stable `ledgerSeq`, and optional immutable timestamp `ts`. These are a portable projected message representation, not the complete provider wire object. [types.ts:1–56](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/types.ts#L1-L56).
- `CompressionBlock` stores `blockId`, `runId`, tier 1/2/3, topic, summary, `directMessageIds`, `effectiveMessageIds`, `directBlockIds`, `compressedTokens`, creation time, survival count, young/old generation, active flag, and optional expanded/restored-inline flags, originating compress call ID, input endpoint refs, and exact ledger interval. It does **not** embed original message bodies in these arrays. [types.ts:58–115](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/types.ts#L58-L115).
- Initial state contains all blocks, bidirectional raw-ID↔display-ref maps, token snapshots, nudge/cadence fields, statistics, absorbed-message records, persistent rules, and counters starting at 1. Block IDs are `b1`, `b2`, …; run IDs `r1`, `r2`, …; active coverage is the union of active blocks' effective IDs. [state.ts:7–64](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/state.ts#L7-L64).
- Message refs have padding floor five (`m00001`), naturally widen, and have a **finite** numeric maximum `9,999,999`. `BLOCKED` is a shared protection sentinel, not a message identity. Ref assignment copies the maps and preserves existing bindings; lifted stale `BLOCKED` protection gets a fresh numeric binding rather than reusing the sentinel as identity. Ref maps are additive; gaps are possible. Host `ledgerSeq` is designed to supply stable display numbering across content-ID churn. [refs.ts:1–145](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/refs.ts#L1-L145); [types.ts:32–42](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/types.ts#L32-L42); [sync.ts:118–132](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/sync.ts#L118-L132).

**Coverage and consumption—these distinctions are essential.**

- A range first has raw-message IDs and nested active blocks. The projection unions selected messages with the effective coverage of blocks it consumes. Direct IDs are IDs not covered by any active block **before this apply call**. Protection/integrity carves must remove IDs from effective coverage as well as direct folding candidates; otherwise prune would hide protected originals anyway. The resulting block stores filtered direct IDs, the effective union, and consumed-child IDs. [unit-projection.ts:206–250](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/unit-projection.ts#L206-L250); [compress.ts:1841–1874](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L1841-L1874).
- Plain message-endpoint folds always output tier 1 and consume nested **tier-1** blocks. A range with **either** endpoint a block ref is a block-boundary fold: target tier is the **minimum** tier among nested blocks (default 1 if none), consumes only nested active blocks of that tier, and outputs `min(3,targetTier+1)`. Thus an ordinary message range can incorporate older T1 summaries without promoting; block-endpoint selection is what requests distillation. A mixed-tier span does not automatically consume every tier. T3→T3 is possible; there is no T4. [unit-projection.ts:206–219](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/unit-projection.ts#L206-L219); [unit-projection.ts:777–790](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/unit-projection.ts#L777-L790).
- Consuming a child marks it inactive, but does not delete its block or summary. This preserves the ancestry graph for restoration/search interfaces. Active coverage, not all historical coverage, controls pruning. [compress.ts:1848–1874](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L1848-L1874); [state.ts:53–64](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/state.ts#L53-L64).
- `compressedTokens` is input mass: token counts of directly folded messages plus the text token counts of consumed summaries. It does **not subtract the new summary's size**, so `tokensCompressed` is not guaranteed net request savings, and hierarchical passes can count the same underlying history at multiple representations. [compress.ts:1816–1829](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L1816-L1829); [compress.ts:831–832](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L831-L832).
- Exact optional `[startSeq,endSeq]` coverage is recorded only if every direct message is ledger-stamped, every consumed block has valid bounds, and their union is one contiguous interval. A hole causes **no interval claim**, not guessed min/max coverage. ID membership remains the fallback. [compress.ts:1881–1931](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L1881-L1931).

**Active/inactive, age, and representation.**

- `syncBlocks` retains the blocks and clones their arrays. Every block referenced as a child by **any** stored block is inactive; explicitly expanded blocks remain inactive. Other blocks are reactivated if any covered base ID, their synthetic summary ID, or a message inside an exact sequence interval is present. Otherwise they are deactivated for absence. This is not age-based GC. [sync.ts:40–175](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/sync.ts#L40-L175).
- `advanceSurvival` increments only active blocks once each time the pipeline's sync node runs; at `survivedCount >= promotionThreshold` it changes generation to `old`. Default threshold is 5. This is **processTurn-pass age, not necessarily five user turns**, and young→old is separate from T1→T2 promotion. No old-generation merge node or generation-based summary concatenation exists in this snapshot's actual pipeline. [state.ts:89–100](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/state.ts#L89-L100); [compress.ts:1250–1257](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L1250-L1257); [compress.ts:1069–1095](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L1069-L1095); [config.ts:23](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/config.ts#L23).
- `prune` replaces covered originals with active summaries (default injection on), removes stale rendered copies of both active and consumed summaries, and cleans orphaned protocol fragments. It deliberately preserves the opening user wire message. If the exact originating compress call is already visible, its arguments already carry the summary, so synthetic rendering for that block is suppressed; once that call leaves, the synthetic representation returns. Summary anchoring is protocol-aware rather than always prepending one recap. [prune.ts:134–238](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/prune.ts#L134-L238); [prune.ts:265–310](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/prune.ts#L265-L310); [prune.ts:451–557](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/prune.ts#L451-L557).

**Protected regions (do not conflate their several definitions).**

- Soft zone is the union of last N visible, noncovered, nonsynthetic ref-bearing messages; a backwards N-token window; and the last real visible user anchor when recent-message protection is enabled. Default N=3 and token window=5,000. Tool-result exceptions can skip the recent window; paired call/result closure adds the other half back if either half is protected. `preserveRecentMessages=0` disables the N/last-user components, but does not by itself disable a positive token window. [recommend.ts:65–197](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/recommend.ts#L65-L197); [config.ts:30–35](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/config.ts#L30-L35).
- Hard filtering includes host message/tool hooks, protected tool/path patterns, latest-only tool instances and matching results, metadata tools, and unrecoverable media/control-plane payloads. Built-in compress-exchange protection has important exceptions: failed exchanges are foldable; only the newest three compress exchanges retain their special fold exemption, and older ones become foldable. Persistent `acp_rule` records remain separately protected. [protected.ts:18–130](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/protected.ts#L18-L130); [protected.ts:346–405](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/protected.ts#L346-L405); [unit-projection.ts:688–774](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/unit-projection.ts#L688-L774).
- Ref-recoverable media (URL/file ID) is foldable; reaccess handles are mechanically appended to stored summaries and carried from children. Unrecoverable media is excluded. This mechanical carry-forward is stronger than merely prompting the model to remember handles. [unit-projection.ts:252–260](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/unit-projection.ts#L252-L260); [compress.ts:1831–1852](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L1831-L1852).

### Inferences
- The useful analogy is a coverage graph with an active summary frontier, not a literal balanced LSM tree. Code permits single-child promotion, same-tier T1 incorporation, mixed-tier spans, and repeated T3 rewriting; no balanced fanout or logarithmic-depth guarantee is enforced. [Supporting implementation](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/unit-projection.ts#L206-L232).
- Retained history can grow while the model-visible frontier stays comparatively small. That is an architectural basis for very long sessions, not proof of truly infinite state or lossless semantic recall. There is a finite ref ceiling, retained block arrays, and a finite context floor. [refs ceiling](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/refs.ts#L3-L25); [terminal condition](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L1596-L1635).

### Gaps
- Long-term original-body retention, ancestry restoration across host-native compaction, and persistence transactions require the storage/retrieval researcher's host analysis; kernel coverage arrays alone cannot guarantee recovery. The relevant handoff is explicit state plus host-provided transcript/content store, not hidden kernel storage. [API contract](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L76-L151).

## 2. What exactly runs, who chooses the summaries, and what can reject or lose content?

### Takeaway
`processTurn` transforms and plans but never invokes an LLM; `applyCompression` validates model-supplied strings and commits coverage changes. The kernel's thresholds and integrity checks are deterministic policy, while semantic selection/compression is externally authored; emergency truncation is an explicitly lossy escape valve with narrower protection than folding. [Pipeline](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L930-L1008); [apply](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L326-L418); [truncate](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/truncate-tools.ts#L38-L149).

### Cited Findings

**Exact default pipeline and external handoffs.** `buildNodes(strategy)` orders: reconcile-live-IDs → stamp-timestamps (optional) → assign-refs → sync-blocks (including survival advancement) → prune → pre-transform-snapshot → ccr-store → absorb-hide → crush → absorb-prompt → filter → hide-compress-calls → relocate-compress-carriers (experimental off) → view-latch → recommend → nudge → emergency-truncate → render-refs (omitted for `renderTags:'none'`). `runPipeline` simply executes enabled nodes sequentially, passing `{messages,state,effects}`. [compress.ts:1069–1095](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L1069-L1095); [pipeline.ts:35–66](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/pipeline.ts#L35-L66).

`processTurn` warns on invalid configuration instead of throwing; takes host `tokenCount` and an injected/default tokenizer; creates an empty content store if omitted; passes optional `applyView` so recommendation uses the same array class as actual execution. It returns rendered messages, updated state, nudge/status line, terminal signal, truncation-skipped reason, and content store. Transport/tool-loop researcher should explain how those outputs get injected and how model calls return to `applyCompression`; storage researcher should explain how all three of state/transcript/store survive. [compress.ts:108–151](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L108-L151); [compress.ts:930–1008](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L930-L1008).

**Recommendation and range resolution.**

- `recommendNode`: computes protected refs, builds candidate ranges, batches physically adjacent candidates to clear `minCompressRange` in **actual characters**, then runs each merged recommended unit through shared `projectUnit`. The screening input is `applyView ?? originalMessages ?? messages`; this avoids recommending a range that only appears legal in a pruned rendering but will fail against the actual fold input. Dead-ref holes and physical protected/pruned gaps are not bridged to achieve the threshold. A subthreshold tail can join its preceding contiguous batch; otherwise it is omitted. [compress.ts:1386–1433](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L1386-L1433); [recommend.ts:575–643](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/recommend.ts#L575-L643).
- `resolveBoundaries` parses m/b refs, resolves them against the supplied visible array, swaps reversed **array positions** with a transparency note, excludes transient synthetic summary/retrieval IDs from durable message membership, and gathers active nested blocks by their visible summary/earliest raw anchor. A block anchor works after raw messages have been pruned. [boundaries.ts:99–179](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/boundaries.ts#L99-L179); [boundaries.ts:440–479](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/boundaries.ts#L440-L479).
- Unknown, consumed, dead, and hidden-orphan refs are not interchangeable. A known consumed child can snap to its visible active ancestor; direct-compression message retries do not silently count as ancestor distillation. Recorded dead/orphan endpoints can snap inward to visible neighbors. An end ref above the highest allocated number clamps to the newest visible ref, but an above-ceiling start is refused. An unallocated hole below the ceiling is unknown, not automatically another session. [boundaries.ts:187–344](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/boundaries.ts#L187-L344); [boundaries.ts:347–432](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/boundaries.ts#L347-L432).
- `projectUnit` is shared by recommendation and execution. Plain ranges exclude host checkpoint carriers of live blocks; block-boundary ranges deliberately allow their distillation. Plain ranges widen reasoning/tool-pair boundaries (composed for up to two passes); block-boundary ranges skip this widening to preserve tier selection. It rescans nested blocks after widening, chooses target/output tiers, computes inherited/direct coverage, and carves protection. [unit-projection.ts:134–250](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/unit-projection.ts#L134-L250); [unit-projection.ts:639–685](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/unit-projection.ts#L639-L685).
- Soft-zone intersections usually carve protected IDs. If a protected message lies inside a range and there is a usable prefix without a straddling tool pair, it cuts the fold at the first protected message, keeping subsequent replies outside too; this avoids anchoring a summary above the question it answers. [unit-projection.ts:262–365](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/unit-projection.ts#L262-L365).
- Integrity withdrawal keeps call/result pairs on the same side and prevents a surviving tool call losing required reasoning. The reverse split (reasoning/prose visible while full call+result folds) is allowed. For merges, check post-fold coverage including unconsumed siblings, and never withdraw IDs whose only old covering block will be consumed; impossible nonregressive merges fail rather than silently uncover originals. [unit-projection.ts:368–503](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/unit-projection.ts#L368-L503).

**`applyCompression` call graph, gates, atomicity.**

1. Clone state; scrub lone Unicode surrogate halves in incoming summary strings; lazily allocate one run ID for mutating candidates. Compute default protected refs unless caller provided a set. Classify each range once with `resolveBoundaries`, recording dead-ref tombstones. [compress.ts:326–444](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L326-L444).
2. Identify possible restored-inline refolds. Sort resolved batch spans by start position; overlapping ranges warn and skip (earliest spatial range wins), instead of rejecting the entire batch. This is distinct from consuming nested blocks from prior calls. [compress.ts:453–515](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L453-L515).
3. Batch size gate sums raw text character counts of accepted resolving message ranges. A block-boundary range exempts the batch; valid pure refolds also bypass it. `minCompressRange` is not a token count or per-summary length. A pure resubmission of already-consumed work returns success-shaped no-op, not an error prompting another retry. [compress.ts:517–673](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L517-L673).
4. Precheck candidate summary lengths across the batch: trim for validation, reject empty/too-short/too-long. `summaryMaxChars` on an individual spec replaces the default max, and max <=0 disables that upper check. An oversized noncandidate consumed skip does not poison a valid sibling. [compress.ts:675–728](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L675-L728); [compress.ts:1933–1967](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L1933-L1967).
5. Keep pre-loop state; for each candidate call `applySingleRange` → `projectUnit` → optional `evaluateRefold`/`applyRefolds` → `validateSummaryLength` → count input tokens → mechanically preserve media refs → `resolveCoverageInterval` → allocate and append new block → deactivate consumed children. A valid inline refold updates existing block summaries in place rather than allocating successors. [compress.ts:294–318](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L294-L318); [compress.ts:730–811](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L730-L811); [compress.ts:1702–1880](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L1702-L1880).
6. Any **apply-level throw** rolls the whole batch back to pre-loop state: no sibling folds commit. However classification-level unknown/invalid refs remain per-range errors and **do not** roll back successful siblings; overlap/consumed skips are warnings. Therefore “all calls are fully atomic” is too broad. Rejected batches may still return updated dead-ref tombstones. Purely protected, already-covered, or filtered-empty work can be a success-shaped no-op. [compress.ts:730–832](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L730-L832); [compress.ts:1720–1813](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L1720-L1813).
7. Successful folds update stats, establish orphan-sweep boundary, reset nudge cadence/baselines and abort debt, update harvest-stall accounting, reset terminal streak, and clear emergency/view/ref-render latches so their refresh rides the fold's own history rewrite. `applyCompression` returns state/result, **not a pruned message list**; subsequent rendering/pruning realizes the new frontier. [compress.ts:831–927](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L831-L927).

**Defaults and real trigger formulas.** Kernel defaults, not necessarily final host overrides:

| Knob | Exact kernel default / consequence |
|---|---|
| tiers | enabled; T2 count trigger 1,000 active T1 blocks; T3 count trigger 2,000 active T2 blocks |
| growth step G | `min(growthCap,max(growthFloor,round(limit*growthRatio)))`; ratio .05, floor=cap=50,000, hence default G=50,000 |
| growth floor F | `max(minGrowthFloor,minGrowthRatio*G)` = `max(20,000,.45*50,000)` = 22,500 |
| pressure | >=75% usage; emergency voice >=95% |
| low-usage marker | .45: relevant to first-sight/backlog bypass, **not a universal lower bound on steady-state nudges** |
| mass thresholds | T1=G; T2/T3=`round(1.5*G)`=75,000 unless individually overridden with `tierGrowthTokens` |
| pressure benefit floor | explicit override, else `max(5000,round(limit*.01))` input-pending tokens |
| summaries/ranges | min range 5,000 **characters**; trimmed summary min 50/max 20,000 **characters**; per-call max override allowed |
| survival/recent | old after 5 active sync passes; recent messages=3 plus recent token window=5,000 |
| fallback | truncate threshold .95; terminal after 3 consecutive stuck events |
| optional lanes | absorb, crush, CCR all disabled by kernel default; absorb/CCR minimum tool size 4,000 tokens |

Pending T1 is only the screened, adequately sized recommended message ranges; pending T2 is the sum of all active T1 summary token counts; pending T3 is all active T2 summaries. Under >=75% pressure, choose the enabled tier with greatest pending mass, gated by minimum benefit; pressure bypasses growth/cadence. Outside pressure, growth must be ready: first-sight mass/backlog bypass, or sufficient measured growth plus eligible abort debt. Normal selection tries T1 first, then T2 by count or enough dominant mass, then T3 by count or mass exceeding both lower tiers; T2/T3 have per-tier cadence. The count path is deliberately extremely high by default, but not literally disabled. [compress.ts:2009–2045](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L2009-L2045); [compress.ts:2048–2307](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L2048-L2307).

Important latest correction in this snapshot: if the first fold answering a T1 nudge harvests less than half the offered input mass, set `t1HarvestStall`; while stalled, qualified T2/T3 mass may go ahead of T1, and pressure can remove T1 from consideration if distillation pays the benefit floor. A distillation clears stall; this is not a semantic score or measured net savings. Abort debt is separate: repeatedly disturbed cadence can bank growth; one abort alone does not activate the debt path. No model network call occurs inside these APIs. **Emergency truncation: explicitly distinguish from a fold.**

- At >=95% host-reported usage, `emergencyTruncateNode` first replays prior latched clips, then calls `truncateLargeToolOutputs` with `includeTextMessages:true` and recent count from config. It aims for `threshold*limit*.9` (default 85.5% of limit). Largest qualifying tool results are clipped first; only then user/assistant text. Candidates are >=1,000 tokens, before the last N array messages, not already marked clipped; output generally preserves ~2,000 prefix + 2,000 suffix characters plus a marker, with Unicode-safe clipping and a strict character-size shrink check. [compress.ts:1531–1594](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L1531-L1594); [truncate-tools.ts:29–149](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/truncate-tools.ts#L29-L149).
- This function does **not call** the normal protected-tool/ref/last-user protection machinery. Thus do not promise all normally fold-protected original text stays verbatim under emergency pressure: even an older large user message or protected tool result can be a truncation candidate. It does preserve recent N array messages, never clips system-role text or synthetic summaries, excludes retrieved text injections, and does not delete whole messages. Tool-call arguments are not candidates. [truncate-tools.ts:51–85](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/truncate-tools.ts#L51-L85).
- Truncation changes returned message text, not a compression block and not a guaranteed original-body archive. Its clips latch by numeric ref and replay even below the watermark until a fold resets them; latch is bounded at 64 entries (oldest dropped), and `BLOCKED` never keys a latch. If no tier has enough pending benefit and truncation saves nothing for 3 consecutive hot events, return `terminalEscape` advising new session or native compaction. Host must deduplicate the warning. Finite irreducible floors are acknowledged explicitly. [compress.ts:1531–1672](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compress.ts#L1531-L1672).

## 3. How do generations accumulate, which regressions support this, and where are docs stale?

### Takeaway
Incremental hierarchical compression keeps many independently located summaries and a recent raw tail, then rewrites selected summary groups only when requested. That avoids rewriting all memory on every turn, but later distillation is deliberately lossy and no kernel check proves that omitted semantics can always be recovered or retained in active context. [tier rules](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/compression-rules.ts#L77-L145); [projection](https://github.com/ranxianglei/billion-context/blob/c3dfbe6b21a1b2fc3642594043bc81fd2ae91247/kernel/src/unit-projection.ts#L206-L232).

    batches = mergeRangesToThreshold(candidates, minCompressRange /* chars */)

applyCompression(input):
    state = cloneState(input.state)
    scrub summary Unicode; derive protected refs; snapshot old active coverage
    classifications = resolveBoundaries(each spec)
    record dead refs; evaluateRefold where relevant
    skip overlapping resolved spans, earliest spatial span wins
    enforce combined raw-char range gate unless block boundary/pure refold
    validateSummaryLength(all actual fold/refold candidates), or reject all
    before = cloneState(state)
    for spec in input order:
        if overlap skip: continue
        if consumed valid inline refold: applyRefolds(...)
        else if consumed: warning/no-op
        else if unknown/invalid: record per-range error; continue
        else: applySingleRange(spec,...)
    if any application throws: return before, zero commits, errors
    update stats; reset cadence/latches if committed; return state + result

applySingleRange(spec,...):
    p = projectUnit(spec,...)
    if p.fatal is zone: return no-op warning
    if p.fatal is split: throw

    if no direct IDs and no children: return no-op

| Step | Request and resulting frontier |
|---|---|
| 1 | Model supplies summary S1 for `m00002..m00020`. Create `b1:T1`, direct/effective IDs 2..20, no children. Prune hides those raws and represents S1; untouched tail stays raw. |
| 2 | Later model supplies S2 for `m00021..m00040`. Create independent `b2:T1`; b1 is unchanged. Active frontier is S1 + S2 + newer raw tail, not `rewrite(S1+everything)` on every turn. |
| 3 | After some sync passes b1/b2 may become `generation:old`, but this alone does not merge them. Model/host submits `b1..b2` with S3. In a pruned apply view, direct IDs can be empty; children `[b1,b2]`; effective IDs 2..40. Create `b3:T2`; b1/b2 inactive but retained. Synthetic `acp_summary_*` IDs do not enter durable coverage. |
| 4 | Later independent folds create `b4:T1`, `b5:T1`; block distillation produces `b6:T2` owning their union. Active frontier now includes b3:T2, b6:T2, and recent raw material. |
| 5 | Model submits `b3..b6` across only these active T2 anchors with S7. Create `b7:T3`, children `[b3,b6]`, effective union inherited from both. b3/b6 deactivate; b1/b2/b4/b5 remain historical descendants. S7 is a third semantic summary generation, not young/old age. |
| 6 | A later T3 group may be rewritten into another T3 block because the output cap is 3. New raw folds may continue beside it; there is no unbounded tier counter. |

The example deliberately assumes a span containing only the intended active tier: if a T1 block lies between two T2 anchors, target tier becomes 1, so the mixed-span operation differs. Also a full raw-log apply view may capture additional directly visible messages within resolved anchors; do not infer every block-ID fold always has empty direct IDs. ### Inferences
- Compared with one rolling summary, independent blocks avoid forcing every new exchange through a complete rewrite of all older memory. Selected old blocks can remain byte-stable for many turns; latches and careful anchors deliberately protect prefix-cache stability. Hierarchical distillation eventually revisits some summaries and may discard increasingly fine detail; it does not remove cumulative semantic-loss risk. - For analogous effectively unlimited memory, retain a separately addressable source archive and make summary omissions recoverable; preserve unresolved objectives as explicit state rather than trusting prose alone; monitor **net** request savings independently of `tokensCompressed`.
