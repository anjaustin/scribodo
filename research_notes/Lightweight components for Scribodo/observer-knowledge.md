# Lightweight observer, narrative knowledge and name/coreference components

## 1. What should remain custom, and where is the actual bottleneck?

### Takeaway
No proven lightweight drop-in was found for Scribodo's complete entity/event/relation/question extraction plus fiction contradiction detection. Keep the custom provenance/authority/store workflow; first borrow deterministic Unicode and conservative name-resolution mechanisms, then benchmark an optional native span extractor, not an agent-memory stack.

### Cited Findings
- Research date 2026-11-25. Local checkout verified as `69b98abf1ecf86c560b435a209327175c182eab1`; no model runs, installations, services or product changes were performed. Local evidence below is **repository-reported measurement/source inspection**, not independently reproduced quality evidence. [Architecture](../../docs/ARCHITECTURE.md); [quality record](../../docs/PRODUCT-GAPS.md).
- Product boundaries are unusually valuable: saved manuscripts remain originals; canon requires author commitment; observer findings are suggestions; Discuss inserts into the visible composer rather than silently injecting a graph into chat. LFM3 generation, Qwen3 embeddings and Qwen3 reranker are already three local models; LFM3 pinned BF16 policy must remain unchanged. [Architecture §§2,9,11](../../docs/ARCHITECTURE.md); [memory authority contract](../../docs/MEMORY-015-effective-memory-contract.md).
- The repository's default historical planted recall is 7/20 and conflict precision 7/92, not a good-performing generic continuity checker. Only 10/20 planted faults reached a judge with their corresponding canon. The sentence path obtained 11/20 recall but 11/60 conflict precision; the same-subject co-signer reports 9/12 precision on **recorded replies**, with only 9/20 recall. These experiments are gated; do not describe the 9/12 row as a new default-on/live result. [PRODUCT-GAPS lines 99–160](../../docs/PRODUCT-GAPS.md); [actual displayed arm table](../../src/llm/observer_arms.c).
- `observer_model_extract` uses the existing LFM3, constrained JSON and at most eight findings per chunk. Subjects are limited to 60 characters, evidence to 300; it asks for names rather than pronouns. `observer_model_judge` uses two order-swapped votes. This is a narrow extraction backend seam, not a reason to replace the entire observer. [observer_model.c](../../src/llm/observer_model.c).
- Chunk discovery has a 3,000-byte chunk / 2,000-byte piece policy and tracks source segments, normalized manuscript newline representation and hashes. Any alternate extractor must bind outputs to the actual immutable source identity, not to a rewritten book. [observer_job.c](../../src/llm/observer_job.c).
- `entity_norm` contains hand-maintained Unicode lowercasing, punctuation stripping and possessive normalization. `a_name` accepts one to four capitalized words plus selected particles, rejecting uncased-script names. `sdb_entity_upsert` merges a unique first-name/full-name association and `fold_entity` moves mentions/links and deletes the derived short-name entity. This is deterministic but can become order-sensitive: a later second full name cannot automatically reconstruct which earlier ambiguous mentions belonged to which person. This last consequence is a source-based inference, not a reproduced bug. [store_entities.c lines 17–215](../../src/app/store_entities.c).
- Existing graph tables already link `entity_mentions(entity_id,finding_id)` and typed links to findings, which link back to source passages. Dismissed/filtered findings do not support visible counts/links. Author canon drafts and source snapshots already exist. A new graph database is not necessary to obtain a provenance graph. [store_entities.c](../../src/app/store_entities.c); [record_workflow.c](../../src/app/record_workflow.c).
- `obs_locate` matches source bytes and normalized variants, including a bounded partial-prefix fallback (at least 60% and 20 bytes under its conditions). A source location proves a quote occurs, **not** that the generated description is entailed by it. Retain this distinction for all alternate extractors. [observer_text.c lines 47–195](../../src/llm/observer_text.c).

### Inferences
- Highest-value custom change is a **mention ledger**: stable project entity IDs, exact source revision/message plus byte spans, observed surface name, explicit author-approved aliases, and separate reversible proposed resolutions. Preserve ambiguous candidate sets rather than destructive first-name folding. Let aliases improve candidate reach; they must not themselves co-sign contradictory facts.
- Native lexical matching over approved aliases may be sufficient initially; an Aho–Corasick index is only justified if measurements show repeated multi-name scanning matters. No additional graph/vector service is justified by this scope.
- Separate mention identity, claim content, story-time interval, source revision time, assertion mode (narration/dialogue/hypothetical), and author canon status. “Later ingested” is neither “later in story time” nor “author-approved replacement.”

### Gaps
- This pass did not reproduce local metrics or measure current Apple Silicon RSS/latency. Historical extraction/contradiction data must not be promoted into independent evidence.
- A perfect deterministic pronoun resolver is not available: ambiguity needs abstention or author confirmation. Unicode repair helps accented names, not pronoun interpretation or truth.

## 2. Which components deserve borrowing or a bounded experiment?

### Takeaway
Rank: **(1) utf8proc**, **(2) selected BookNLP name-clustering ideas and literary fixtures**, **(3) GLiNER-small through GLiNER.cpp as a measured optional extractor**, **(4) Graphiti provenance/temporal schema ideas only**, **(5) fastcoref as an offline comparator only**. The first requires no new model; the others do not establish a fiction-contradiction improvement.

#### 1 — utf8proc: small direct replacement for incomplete text primitives
- Verified SHA `f72a4023617e2d879f2ca93086fd02bc7e3149fe`, patch date **2026-10-14**; project version **2.12.0**, released **2026-09-25**, Unicode 18 support. These are upstream facts, not a benchmark. [commit/patch](https://github.com/JuliaStrings/utf8proc/commit/f72a4023617e2d879f2ca93086fd02bc7e3149fe.patch); [NEWS](https://github.com/JuliaStrings/utf8proc/blob/f72a4023617e2d879f2ca93086fd02bc7e3149fe/NEWS.md).
- CMake builds a C library from `utf8proc.c`/header and generated data, supports static linkage, and includes case/normalization/grapheme/fuzz tests. No Python runtime, network service or model is needed. The build's optional Unicode test-data downloads should be pinned/vendored for offline reproducibility. [CMake](https://github.com/JuliaStrings/utf8proc/blob/f72a4023617e2d879f2ca93086fd02bc7e3149fe/CMakeLists.txt); [API](https://github.com/JuliaStrings/utf8proc/blob/f72a4023617e2d879f2ca93086fd02bc7e3149fe/utf8proc.h).
- Code MIT, tables have Unicode data permission notice: retain both. Weight license: **not applicable**. Mature Unicode conformance evidence is relevant to name-key correctness; it is not literary NER/coreference evaluation. [license](https://github.com/JuliaStrings/utf8proc/blob/f72a4023617e2d879f2ca93086fd02bc7e3149fe/LICENSE.md).
- **Scribodo seam/inference:** replace `lower_cp`/capitalization primitives and define a versioned NFC+casefold lookup-key policy in `entity_norm`; preserve original name/source strings. Do not transliterate, strip accents or apply compatibility folding indiscriminately to identity. Changing keys needs a collision-aware migration and old-key aliases, not silent merging. Normalized keys cannot be used as source byte offsets.
- **Cost:** zero fourth model, zero extra process. Static Unicode tables + transient mapped-string allocation; actual linked-size/RSS delta not measured.

#### 2 — BookNLP: selective algorithms and literary error taxonomy
- Verified SHA `3d900fc2224e55960c3363826ae28539b77b4204`, **2024-07-12**, setup version **1.0.7**. Relatively old visible head means mature research reference, not evidence of a current actively maintained native distribution. Code MIT. [commit](https://github.com/booknlp/booknlp/commit/3d900fc2224e55960c3363826ae28539b77b4204.patch); [license](https://github.com/booknlp/booknlp/blob/3d900fc2224e55960c3363826ae28539b77b4204/LICENSE).
- `NameCoref.get_canonical` allows multiple nickname interpretations; `get_variants` indexes ordered name subsets, excludes bare honorifics; clustering uses observed name counts and recency. Code also distinguishes quote-external first-person narrator mentions. This is compact algorithm source worth studying, but its nested subset enumeration and O(names²) comparisons are **not** a recommendation to copy verbatim into bounded host code. [name_coref.py](https://github.com/booknlp/booknlp/blob/3d900fc2224e55960c3363826ae28539b77b4204/booknlp/english/name_coref.py).
- Official README explicitly warns full book coreference erroneously conflates distinct entities. Default resolves names first, then pronouns, and disallows common-noun→proper-name merging. It acknowledges book-scale coreference remains open. This supports conservative candidate generation and abstention rather than automatic destructive canonicalization. [README coreference section](https://github.com/booknlp/booknlp/blob/3d900fc2224e55960c3363826ae28539b77b4204/README.md#character-name-clustering-and-coreference).
- Upstream reports small/big entity F1 **88.2/90.0**, event F1 **70.6/74.1**, coreference average F1 **76.4/79.0**. *Secret Garden* 99K-token timing: **3.6/15.4 min on 2019 MacBook Pro CPU**. These are author-reported historical linguistic scores/timing, **not M4 measurements or contradiction accuracy**. [README table](https://github.com/booknlp/booknlp/blob/3d900fc2224e55960c3363826ae28539b77b4204/README.md).
- Training/eval provenance is substantially closer to fiction than OntoNotes: LitBank, literary entity annotations, PreCo for coreference; event tags target asserted realis rather than hypothetical/future events. Entity training includes a stated 968K-token collection with contemporary fiction; annotation/dataset availability and licenses must be cleared before copying fixtures. [README annotations](https://github.com/booknlp/booknlp/blob/3d900fc2224e55960c3363826ae28539b77b4204/README.md#annotations); [LitBank](https://github.com/dbamman/litbank).
- **Scribodo seam/inference:** port bounded title/variant candidate indexing into a new reversible resolver beside `sdb_entity_upsert`; keep explicit author aliases strongest, ambiguous nicknames as candidates, no recency-driven identity co-signing. Add literary modality and quote attribution negatives to `test_observer_text` and observer fixtures. Do not infer a character's gender identity from name or pronoun priors.
- **Cost:** selected pure name algorithms add no model/process. Full pipeline adds Python plus multiple BERT-task weights and spaCy; neither full RAM nor separate Berkeley-downloaded weight license was established. MIT repository license must not be treated as blanket weight/data clearance.

#### 3 — GLiNER native inference: bounded span extraction experiment
- Native repo SHA `af99d2b1fddbfde644e07b159730a76f876ae517`, commit page authored/committed **2026-07-10**, CMake project **0.0.2**, Apache-2.0 code. It is a substantially younger integration than utf8proc; version number is not a performance/maturity guarantee. [commit](https://github.com/Knowledgator/GLiNER.cpp/commit/af99d2b1fddbfde644e07b159730a76f876ae517); [build](https://github.com/Knowledgator/GLiNER.cpp/blob/af99d2b1fddbfde644e07b159730a76f876ae517/CMakeLists.txt); [license](https://github.com/Knowledgator/GLiNER.cpp/blob/af99d2b1fddbfde644e07b159730a76f876ae517/LICENSE).
- C++ inference uses ONNX Runtime and tokenizer.json; documented CPU build includes Rust/Cargo, ONNX Runtime, OpenMP; inspected CMake fetches PCRE2 10.44. GPU instructions describe CUDA/NVIDIA, **not Apple Metal acceleration**. A narrow `extern "C"` adapter can integrate in-process, but no stable existing C ABI/macOS arm64 validation was established. [README](https://github.com/Knowledgator/GLiNER.cpp/blob/af99d2b1fddbfde644e07b159730a76f876ae517/README.md); [decoder API](https://github.com/Knowledgator/GLiNER.cpp/blob/af99d2b1fddbfde644e07b159730a76f876ae517/include/GLiNER/decoder.hpp).
- Specific conservative model: `urchade/gliner_small-v2.1`, **166M parameters**, English, Apache-2.0 weights; HF revision `4e091416cf7c3481db542c2a3d26156916f3a47f`, modified **2024-04-10**. Older v0/v1 weights are NC; don't accidentally substitute them. [revision-pinned card](https://huggingface.co/urchade/gliner_small-v2.1/blob/4e091416cf7c3481db542c2a3d26156916f3a47f/README.md); [metadata API](https://huggingface.co/api/models/urchade/gliner_small-v2.1).
- **Cost estimate, not measured:** 166M × 4 bytes ≈ **664 MB decimal FP32 weights**; 332 MB at two-byte representation, but representation/backend support must be checked rather than assumed. ONNX Runtime, activations, tokenizer and allocator add overhead. This would be a **fourth model**, not a replacement for the three existing roles; in-process avoids an extra resident service but not RSS/CPU contention.
- Current upstream also offers joint RelEx, but do not conflate it with what the native wrapper supports. `knowledgator/gliner-relex-large-v1.0` has Apache-2.0 card, revision `4aedc9226a5ac9e2f6b5ea3e91c1ee577c88a290`, modified **2026-03-22**, HF metadata **466,576,896 FP32 parameters** (~1.87 GB weight-only). Card claims joint NER+relations and ONNX export. No verified native-wrapper RelEx parity, novel eval or coreference was found. [pinned card](https://huggingface.co/knowledgator/gliner-relex-large-v1.0/blob/4aedc9226a5ac9e2f6b5ea3e91c1ee577c88a290/README.md); [metadata](https://huggingface.co/api/models/knowledgator/gliner-relex-large-v1.0).
- **Scribodo seam/inference:** return `{type,start_byte,end_byte,surface,score,extractor_revision}` candidates into the observer before canon pairing; verify exact spans through original source mapping. Use NER to improve entity/sentence reach, not to create entity facts from names alone. Keep LFM3 event/question/semantic judge initially. No evidence that ordinary NER improves conflict precision.

#### 4 — Graphiti: valuable schema, wrong authority engine
- Verified SHA `38eef1eb9f9e993effc9801d64cb73aaf9d3cbbd`, **2026-11-25**, project manifest **0.32.1**, Apache-2.0. Head patch only adds a CLA signature; inspected schema/build files are pinned to it, not a claim that that patch introduced the architecture. [commit](https://github.com/getzep/graphiti/commit/38eef1eb9f9e993effc9801d64cb73aaf9d3cbbd.patch); [manifest](https://github.com/getzep/graphiti/blob/38eef1eb9f9e993effc9801d64cb73aaf9d3cbbd/pyproject.toml).
- `EntityEdge` carries endpoint IDs, relation name, generated fact, fact embedding, episode IDs, `created_at`, `expired_at`, `valid_at`, `invalid_at`, and `reference_time`; `group_id` partitions edges. This is concrete temporal/provenance schema worth learning from. Episode linkage does not by itself supply exact manuscript substring verification. [edges.py](https://github.com/getzep/graphiti/blob/38eef1eb9f9e993effc9801d64cb73aaf9d3cbbd/graphiti_core/edges.py).
- Maintenance stages explicitly separate extraction and resolution, constrain edge signatures/endpoints, and track invalidated edges. Extraction remains LLM-driven; automatic invalidation is a semantic decision, not an author-controlled canon action. [edge_operations.py](https://github.com/getzep/graphiti/blob/38eef1eb9f9e993effc9801d64cb73aaf9d3cbbd/graphiti_core/utils/maintenance/edge_operations.py).
- Python ≥3.10, Neo4j/OpenAI/numpy dependencies, optional FalkorDB/FalkorDBLite and alternative integrations: **not necessarily mandatory cloud or external server in every configuration**, but still an unnecessary new Python framework/graph lifecycle for Scribodo. No new model weights intrinsic to copied schema; full adoption still requires LLM/embedder configuration and workload-dependent graph/embedding cost. [manifest](https://github.com/getzep/graphiti/blob/38eef1eb9f9e993effc9801d64cb73aaf9d3cbbd/pyproject.toml).
- **Scribodo seam/inference:** enrich existing finding-backed links with explicit source/support edges and optional story-time labels; use `record_versions` for author status. Never let graph “expired” truth revise canon, delete originals, or widen conversation consent. Unknown story dates stay unknown.

#### 5 — fastcoref: comparison oracle, not deployment recommendation
- Verified SHA `ae224139196d122b225af5a7e73b5fc0b6e1076d`, **2026-05-21**, manifest **2.2.3**, MIT code. Current manifest requires Python 3.11–3.13, torch, transformers, spaCy, numpy/scipy, datasets, pandas, wandb, sentencepiece and more; deployment is not “one tiny model.” [commit](https://github.com/shon-otmazgin/fastcoref/commit/ae224139196d122b225af5a7e73b5fc0b6e1076d.patch); [manifest](https://github.com/shon-otmazgin/fastcoref/blob/ae224139196d122b225af5a7e73b5fc0b6e1076d/pyproject.toml).
- F-coref weight card independently says MIT; HF revision `e91dfff12879495d882ba9460d0c5d5dd44ade59`, **2022-11-28**. Model card reports **78.5 average F1 on OntoNotes**, **25 s / 4.0 GiB for 2.8K docs on V100** with batching. These author results are not CPU/M4 RAM forecasts and not whole-novel or contradiction validation. [pinned model card](https://huggingface.co/biu-nlp/f-coref/blob/e91dfff12879495d882ba9460d0c5d5dd44ade59/README.md); [metadata](https://huggingface.co/api/models/biu-nlp/f-coref).
- API returns original character-span clusters and pair logits, a better interface than rewriting a source with pronouns replaced. README also offers resolved-text output; do not store that rewrite as source evidence. [README](https://github.com/shon-otmazgin/fastcoref/blob/ae224139196d122b225af5a7e73b5fc0b6e1076d/README.md).
- **Scribodo seam/inference:** if separately authorized, use an isolated offline benchmark to estimate whether learned pronoun clusters recover misses beyond explicit aliases; import only annotated span proposals, never runtime Python. A future native port would be substantive tokenizer/model/postprocessing work, not a free C binding.

### Inferences
- Smallest comprehensive solution is likely **existing custom observer + better deterministic mention identity + one optional span model only if it earns its resources**. Name algorithms and source-linked schema can be borrowed without acquiring the upstream orchestration.
- No reason was found to replace MariaDB link/mention tables with a graph service. A graph representation is not synonymous with a graph database.
- Weight-only arithmetic dramatically understates deployment cost: count fourth-model residency, tokenizer/runtime, scratch memory, cancellation, restart/package signing, model-download integrity and foreground contention.

### Gaps
- GitHub API returned HTTP 429; serious-option SHAs were verified from repository HTML and files/patches instead. Screen-only candidates are intentionally not presented as pinned adoption-ready packages.
- GLiNER.cpp arm64 macOS compilation, native token/span offset parity, exported-weight size/hash, runtime accuracy, and binary dependency closure remain unmeasured. No architecture claim from current GLiNER README proves the older native wrapper implements it.
- BookNLP downloaded neural weights and ancillary alias/gender/data assets need explicit separate redistribution review. LitBank fixture license and held-out overlap must be cleared before reuse. No serious option has independently demonstrated Scribodo fiction-contradiction precision.
- Whole-product alternatives and LlamaIndex-style orchestration were not recommendations; adding more framework survey would not change the identified extraction/identity seams.

## 3. What falsifiable experiment and safety gates would justify adoption?

### Takeaway
Run extraction and identity ablations on fresh novels, holding the current judge and BF16 model contract fixed. Ship nothing unless exact-source/authority invariants hold and end-to-end conflict precision improves or stays above the agreed threshold while recall crosses it within explicit whole-system budgets.

### Cited Findings
- Scribodo's stated gates include recall ≥0.50, place recall 1.00, conflict precision ≥0.50, entity precision ≥0.60 with empty entities ≤0.10, event ≥0.80, question ≥0.60 and relationship ≥0.75, with no metric below its prior baseline. These are **repository/author-agreed gates**, not external NLP benchmarks. [PRODUCT-GAPS lines 124–160](../../docs/PRODUCT-GAPS.md).
- Reach and faithful use must remain separate; consent/canon never widens model access, generated aids remain noncanonical, and absence is bounded coverage. Those constraints apply equally to new extraction models and deterministic alias indices. [MEMORY-015 §§5–7](../../docs/MEMORY-015-effective-memory-contract.md).
- Observer scheduling already showed zero backlog drainage during the reported continuous-chat workload; adding a faster non-generative extraction stage could help, but cannot guarantee drainage when LFM3 judging still monopolizes the shared generation gate. [PRODUCT-GAPS scheduling record](../../docs/PRODUCT-GAPS.md); [observer backend](../../src/llm/observer_model.c).

### Inferences
- **Pre-register corpus:** two or more previously untouched, legally usable novel-length manuscripts, one unlike 19th-century English and one with multiple same-surname characters, accented/decomposed names, aliases, epistolary/quoted speech, pronoun-heavy scenes, flashbacks, unreliable speakers, hypothetical plans and changed facts. Exclude LitBank/BookNLP training overlap when possible; mark remaining pretraining contamination uncertainty.
- **Ablations, no prompt retuning:** A=current production; B=Unicode primitives only; C=B+explicit author aliases+reversible ambiguous mention ledger; D=C+GLiNER-small native NER candidates; optional E=offline literary/coref comparator after separate authorization. Freeze LFM3 weights/BF16 execution, prompts, canon entries and judge budget. Record all candidates before selection so extraction recall cannot be hidden by judge precision.
- **Gold labels:** exact source/revision byte ranges; mention identity and deliberately ambiguous cases; entity/event/relation/question finding types; conflicting claim pairs, nonconflicting additions, dialogue claims, story-time changes and canon supersession. Use two annotators/adjudication where feasible; distinguish story claim from author's canon decision.
- **Metrics:** mention/name recall, false merge rate, pronoun resolution coverage/precision and abstention; finding precision/recall by type; source-span validity (must be 100% for published citations); canon-pair reach; end-to-end planted/natural contradiction recall and precision separately. Include confidence intervals and per-book results, not just pooled means. False merges matter independently because they can turn a correct fact into a false conflict.
- **Cost:** cold/warm wall time per 100K words, native binary/dependency/download size, peak incremental and total RSS (including three existing model processes/services), CPU/thread count, UI frame outliers, time to first chat token, interrupted-job wasted work, and backlog under the same continuous-chat cadence. Proposed optional-model screen: incremental steady RSS ≤1 GiB and no statistically/materially worse foreground latency; author should agree limits before measurement, not inherit this proposed cap as policy.
- **Stop conditions:** any source mismatch, canon mutation without author action, chat injection, cross-project/scope leak, silent cloud fallback, or irreversible merge fails the experiment regardless of NLP scores. Reject a fourth model if C's cheap deterministic changes achieve equivalent held-out reach/precision within uncertainty.
- **Safety fixture matrix:** same first name introduced late; Mr/Mrs sharing surname; one alias shared by two people; inherited title; identity reveal and disguise; narrator switch; plural “they”; singular “they”; unnamed antecedent; quoted “I”; decomposed Unicode; sentence-initial common noun; retracted canon; obsolete revision; deleted chat that once supported a link; author-retained canon with removed source link. Neither latest source timestamp nor model confidence authorizes promotion.
- **Deletion/rebuild rule:** source removal invalidates eligibility/support and schedules index cleanup; retain immutable/versioned originals according to the actual product policy, and keep author-saved canon/notes distinct from disposable derivations. Rebuild the mention graph from source IDs plus retained resolution decisions, never from generated summaries.

### Gaps
- Natural fiction contradiction adjudication is costly and ambiguous; planted errors alone are insufficient. Agreement and book-specific limits must be reported.
- No projected improvement percentage is defensible before these ablations. The research supports what to test and where to borrow, not a claim that any library fixes fiction continuity.
