# Compose mature parts; keep author authority

**Scribodo should buy mature mechanisms, not another writing product or memory architecture.** Ranked by potential reduction in total maintenance and operational weight, the best opportunities are **SQLite + FTS5 for structured storage**, a **direct AppKit text island informed by libui-ng**, **eligibility-first exact vector search through sqlite-vec**, **utf8proc for derived lookup keys**, and **consolidation onto already-linked libcurl**. These are conditional integrations, not an all-at-once rewrite: keep MariaDB and Qdrant as working controls until replacements pass parity and cost gates. Immediately retain and security-maintain llama.cpp, and add development-only libFuzzer rather than another production framework. For narrative observation, borrow conservative BookNLP name-resolution ideas before considering a fourth model. The cohesive optional target is the existing C workbench and raylib/Clay shell, platform-native manuscript editing, one embedded relational store with lexical/exact-vector facilities, and the existing pinned local model processes—with Scribodo still owning every author-authority decision.

**November 25, 2026.** This report synthesizes five completed source/build/license investigations against baseline `69b98abf1ecf86c560b435a209327175c182eab1`, plus the source-traced architecture and open repository audit. It is **not a benchmark, prototype, fresh model evaluation, or distribution clearance**. Upstream facts below were documented in those investigations; proposed benefits and migration designs are engineering judgments. No new web research, implementation, installation, or service launch was performed for this synthesis. Detailed evidence is available in the [native-authoring notes](../research_notes/Lightweight%20components%20for%20Scribodo/native-authoring.md), [storage-recovery notes](../research_notes/Lightweight%20components%20for%20Scribodo/storage-recovery.md), [retrieval-indexing notes](../research_notes/Lightweight%20components%20for%20Scribodo/retrieval-indexing.md), [inference-verification notes](../research_notes/Lightweight%20components%20for%20Scribodo/inference-verification.md), and [observer-knowledge notes](../research_notes/Lightweight%20components%20for%20Scribodo/observer-knowledge.md). The [architecture](../docs/ARCHITECTURE.md) and [AUDIT-005](../docs/AUDIT-005-repository-audit.md) are baseline implementation evidence, not previous upstream component research.

## Keep the workbench; replace mechanisms that earn their cost

Scribodo already reuses raylib, Clay, stb, cJSON, llama.cpp and MariaDB Connector/C. It is not a blanket NIH project. Its unusually well-tailored custom code distinguishes conversation, manuscript, note, committed canon and observer suggestion; refuses a second structured history when a marked backend is unavailable; checks exact original text before accepting anchored edits; and treats vector results as untrusted locators. Generic writing, RAG or agent frameworks do not replace those responsibilities. They usually add a second orchestration model while leaving source receipts, consent, admission and recovery work intact. Keep `project_store.c`, `reviewed_edit_controller.c`, the authority parts of `record_workflow.c`, `context_planner.c`, `generative_gate.c`, `answer_pipeline.c` and `answer_receipt.c` custom unless a narrower mechanism can be removed without weakening their contracts. This is a fit judgment, not a claim that the existing implementation is defect-free. ([Architecture](../docs/ARCHITECTURE.md))

The shortlist below ranks architectural opportunity, **not execution order or demonstrated speed**. “Prototype” means isolate and test before adoption; “borrow” means ideas or license-reviewed bounded code, not importing the whole repository. Exact inspection pins are distinguished from verified releases. Entries without learned weights have no model license; code licenses never clear unrelated weights or datasets.

## SQLite can simplify operations, not erase recovery contracts

**SQLite is the strongest simplification candidate because it can remove an operational subsystem, not merely shorten an API wrapper.** `src/app/db.c` currently owns Connector/C connection setup, asynchronous socket/deadline polling and migration adaptation. SQL in `memory_store.c`, `memory_document_store.c`, `store_records.c`, other `store_*.c` files and `recall.c` uses MariaDB locking, upserts, timestamps and full-text behavior. A SQLite migration therefore means deliberate SQL and transaction redesign, plus changes to `project_store.c`, `service_supervisor.c`, `tools/services*.sh`, `tools/backup.sh` and `tools/restore.sh`. A small checked adapter around prepare/bind/step/finalize fits the C11 application better than an ORM. Potential removals include credentials, DB ports, reconnect/health logic, native-versus-Docker database handling and dump tooling; **no net LOC or RSS saving was measured**. ([Storage source analysis](../research_notes/Lightweight%20components%20for%20Scribodo/storage-recovery.md))

Keep/harden the current baseline—MariaDB **11.4.13**, Connector/C **3.4.11**—until parity. Connector/C's C API is already integrated; client LGPL-2.1 distribution obligations and the separate GPLv2 server remain costs, not evidence that the backend is unsuitable. The moved MariaDB image tag requires investigation, not an automatic digest update. More urgently, audit **F1–F3 are caller-policy defects**: failed file-backed chat appends bypass the unsaved guard; truncated/sanitized filenames collide in revision identity; successful file-backed retries remain marked and can append again. Fix persistence-state reporting, stable identities and successful-append acknowledgement in their callers regardless of database choice. The audit remains open; a component report resolves none of it. ([Connector release](https://github.com/mariadb-corporation/mariadb-connector-c/releases/tag/v3.4.11), [AUDIT-005](../docs/AUDIT-005-repository-audit.md))

SQLite WAL permits readers alongside **one writer**, not concurrent writers without contention. Use short transactions, thread-owned connections or a bounded writer queue, explicit cancellation/busy handling and checkpoints that cannot indefinitely grow the WAL. Preserve source row, receipt/cursor and outbox intent in the same transaction; claim briefly, perform model/index work outside it, then acknowledge only matching owner/fence/generation. A single process does not make stale-worker fencing obsolete. Port `FOR UPDATE` and upserts deliberately; `INSERT OR REPLACE` is not a safe mechanical substitute. FTS5 external-content consistency also remains an application transaction/trigger obligation. ([SQLite transactions](https://sqlite.org/lang_transaction.html), [WAL](https://sqlite.org/wal.html), [FTS5](https://sqlite.org/fts5.html))

Pin the actual SQLite library rather than trusting the system copy. The storage notes verified stable **3.54.1** and distinguish its Git tag from its official Fossil source ID. Official documentation reports the **WAL-reset race affecting versions through 3.51.2, fixed in 3.51.3 and later with selected older backports**, involving concurrent writing/checkpointing connections. That is a version-specific warning, not a claim that WAL is generally unsafe. Evaluate `synchronous=FULL` and macOS `fullfsync=ON` for the intended acknowledgement contract; `NORMAL` can lose acknowledged transactions after power loss. SIGKILL testing does not prove drive-cache durability. ([Official release history](https://sqlite.org/changes.html), [WAL-reset warning](https://sqlite.org/wal.html#walresetbug), [fullfsync](https://sqlite.org/pragma.html#pragma_fullfsync))

**SQLite cannot atomically commit a manuscript file and database state.** `doc_io.c` already writes an exclusive sibling, syncs, rechecks external modification, renames and syncs the parent; its remaining race and discarded parent-sync failures need focused hardening. Borrow sequencing/error-state lessons from [libgit2's file buffer](https://github.com/libgit2/libgit2/blob/49e408b3208bc3093757a1c2db938d3590f3f412/src/util/filebuf.c) and [SQLite's Unix VFS](https://github.com/sqlite/sqlite/blob/57520227c95396ce39ba6ecaac8d475b78dd3964/src/os_unix.c), not their private utilities as unsupported standalone libraries. A proposed save-intent journal can record expected old/new file identities and revision IDs, then reconcile after rename/crash without overwriting external changes. Preserve the distinctions among source snapshot, unsaved accepted edit, saved revision and recovery draft. ([Current contracts](../docs/ARCHITECTURE.md#5-writing-saving-and-recovering-a-document), [Storage analysis](../research_notes/Lightweight%20components%20for%20Scribodo/storage-recovery.md))

Keep immutable SQL revisions instead of adding Git as writing-history authority. [libgit2 **v1.9.7**](https://github.com/libgit2/libgit2/releases/tag/v1.9.7), source `49e408b3…`, is a mature C library under GPLv2 with a linking exception and bundled notices, but objects/refs/packing/GC plus SQL-to-blob mapping introduce another consistency boundary. Prototype only for a real Git interoperability or measured compression requirement. SQLite online backup is the embedded database primitive; stage it with separately verified manuscripts and a complete manifest, rather than copying an active main database without its WAL. It still yields no automatic whole-project snapshot. ([Online backup](https://sqlite.org/backup.html), [libgit2 license](https://github.com/libgit2/libgit2/blob/49e408b3208bc3093757a1c2db938d3590f3f412/COPYING))

Defer [libarchive **v3.8.11**](https://github.com/libarchive/libarchive/releases/tag/v3.8.11), source `03036ffa…`, mostly BSD-2-Clause with per-file exceptions, unless a restricted streaming archive actually replaces current directory-copy helpers. Compression/crypto dependencies and secure extraction flags require explicit configuration; archive “safe writes” are not a multi-file transaction. [restic **v0.20.0**](https://github.com/restic/restic/releases/tag/v0.20.0), source `9c88ff76…`, BSD-2-Clause, is an **optional external offline retention tool**, not a production writing dependency: its Go binary, substantial dependencies, keys and pruning policy earn their cost only when deduplication/encryption/retention are wanted. Feed it completed consistent bundles, not live database files. ([Archive safety/source](https://github.com/libarchive/libarchive/blob/03036ffa409a2aa1c5bbad35be2202641a040fda/libarchive/archive.h), [Restic source/build](https://github.com/restic/restic/tree/9c88ff768f10c192dc6a87619a65a16374080e33))

## Native text and exact search address different missing maturity

The current custom editor uses codepoints, not grapheme indices; committed `GetCharPressed()` input is not a marked-text interface. `font.c` has fixed glyph coverage and per-codepoint drawing; `wrap.c` sums scalar advances. Those are genuine input/layout gaps, unlike pane layout, where raylib/Clay already fit. Prototype `src/platform/text_view_mac.m/.h`, host it through the existing `NSWindow` access in `mac_window.c`, and frame it from `layout.c`. Preserve the public `Editor` range/dirty/save/anchor interface, `doc_io.c`, drafts, revisions and reviewed-edit controller. [libui-ng's MIT multiline entry](https://github.com/libui-ng/libui-ng/blob/43ba1ef553c8993a43a67f1ce6e35983a2660d8c/darwin/multilineentry.m) demonstrates an opaque C/Objective-C bridge and disables automatic substitutions; **do not bring its whole control/layout/event toolkit alongside the existing shell**. Cocoa and Objective-C compilation already exist in the build. ([Native-authoring evidence](../research_notes/Lightweight%20components%20for%20Scribodo/native-authoring.md))

AppKit capability is not proven integration. The hard work is incremental UTF-16 range ↔ UTF-32 position ↔ original UTF-8-byte mapping, composition lifecycle, one undo authority, focus/shortcuts, scrolling/Retina geometry and live proposal anchors. Do not keep two independently editable buffers or round-trip the manuscript each frame. Disable automatic text replacement and treat system rewriting as an author-controlled proposal boundary. Explicitly choose TextKit behavior: accessing `layoutManager` can switch modern NSTextView into compatibility mode, and the older exemplar uses NSLayoutManager. Test IME, VoiceOver, mixed bidi, Indic clusters and long manuscripts in the actual raylib window; native text does not make surrounding custom controls accessible. Its resident allocations and transition-time duplicate storage are unmeasured. ([Apple NSTextView](https://developer.apple.com/documentation/appkit/nstextview), [Input protocol](https://developer.apple.com/documentation/appkit/nstextinputclient))

If custom text surfaces remain, choose segmentation by need. [libgrapheme](https://github.com/FRIGN/libgrapheme/tree/bf20d2f7bce13c7d006a9ca442221399753bce9d), inspected version declaration **3.0.0**, Unicode 17, ISC plus Unicode notice, offers UTF-8/32 grapheme/word/line APIs and current bidi operations. [libunibreak](https://github.com/adah1972/libunibreak/tree/9266fa15190eb2017476e6315b5176143a8f80b3), inspected Nov 24 HEAD, zlib-style plus Unicode terms, is an alternative UTF-8/16/32 breaking layer. Neither inspected HEAD is automatically a verified published release. **utf8proc normalization/properties and segmentation libraries are not interchangeable**: utf8proc has stateful grapheme boundaries but not complete word/line breaking or shaping. Select one segmentation layer where possible; add utf8proc separately only for a distinct lookup/property need. Adapt gap-buffer access safely and vendor generated tables/fixtures for offline builds. Never normalize authoritative manuscript bytes, source identities or offsets. ([Native API/build/license comparison](../research_notes/Lightweight%20components%20for%20Scribodo/native-authoring.md))

[HarfBuzz](https://github.com/harfbuzz/harfbuzz/tree/4c4ae97002cc46fff10ff40d6b7e0d1d967200dd), inspected build version **15.2.0**, Old MIT core, is a C-callable C++ shaper, **not a complete editing system**. Its glyph IDs, clusters, advances and offsets would require coordinated changes to rendering, wrapping, hit-testing and selection, plus fallback, rasterization, bidi and native input/accessibility work. Compare platform CoreText first on this Mac-only target; do not import HarfBuzz's expanded default feature set and call it minimal. [STTextView](https://github.com/krzyzanowskim/STTextView/tree/c7d519318b06ebb7a99a641e4aa8831105d3b7d4) is a useful behavioral reference but **current GPLv3/commercial licensing can disqualify integration or source copying into the MIT product**. Its inspected manifest adds Swift tools 5.9, macOS 14 minimum and STTextKitPlus/CoreTextSwift dependencies whose full license graph was not audited. Plain NSTextView is the lower-incremental-dependency experiment, not a proven winner. ([HarfBuzz options](https://github.com/harfbuzz/harfbuzz/blob/4c4ae97002cc46fff10ff40d6b7e0d1d967200dd/meson_options.txt), [STTextView license](https://github.com/krzyzanowskim/STTextView/blob/main/LICENSE.md), [Manifest](https://github.com/krzyzanowskim/STTextView/blob/c7d519318b06ebb7a99a641e4aa8831105d3b7d4/Package.swift))

Retrieval needs a separate measured-scale decision. **First benchmark current Qdrant exact mode against its ANN mode**, with actual payload indexes and cardinalities inspected. Scribodo pins **1.20.0**; research observed **1.20.2**, Nov 16, Apache-2.0, not evidence that the current integration is broken. Next test release-pinned sqlite-vec exact plus FTS5, initially as a rebuildable sidecar if MariaDB stays authoritative. This adds a derived SQLite store before it removes anything; it is independent of the primary-storage migration. Only try ANN if exact search misses an agreed cost budget. Keep SQL hydration, tuned rank fusion, source admission and receipts. ([Qdrant release](https://github.com/qdrant/qdrant/releases/tag/v1.20.2), [Exact search controls](https://qdrant.tech/documentation/concepts/search/), [Retrieval analysis](../research_notes/Lightweight%20components%20for%20Scribodo/retrieval-indexing.md))

Eligibility must constrain scoring **before top-k**: consent scope, attached saved revision, message cutoff, model fingerprint and generation are not post-search decorations. For sqlite-vec, prove metadata/partition/allowed-ID query behavior; an outer join after KNN truncation is insufficient. An explicitly eligible FLOAT32 relation with scalar distance is a valid correctness oracle. Preserve `memory_vectors.h` locators and `memory_candidate_hydrate*`; no cached payload text enters the prompt. Qdrant cannot disappear until the **older observer/canon semantic index and the newer consent-scoped memory index** both migrate—their protocols differ. Revalidate authorization at dispatch even after an eligibility snapshot. ([Current planner/index seams](../research_notes/Lightweight%20components%20for%20Scribodo/retrieval-indexing.md))

For justified ANN, [USearch **v2.26.6**](https://github.com/unum-cloud/usearch/tree/v2.26.6), Oct 25, Apache-2.0, is the strongest released C-facing challenger: filtered search, exact search, remove and persistence APIs, native C++ internals, optional acceleration and threading requirements. Its checked main is materially different 3.0/C++20-era machinery; do not mix APIs or concurrency claims across them. Host-owned locator maps, immutable generations, checkpoint publication and churn/rebuild policy remain. [SQLite-Vector **1.2.0**](https://github.com/sqliteai/sqlite-vector/tree/1.2.0), Apache-2.0 root, is a secondary exact-scan candidate: four-argument `vector_full_scan(...,k)` performs internal top-k, so outer authorization loses candidates; three-argument streaming plus verified filtering/order avoids that error. Bundled FP16 notice closure was unresolved, lowering adoption readiness. ([USearch C API](https://github.com/unum-cloud/usearch/blob/v2.26.6/c/usearch.h), [SQLite-Vector implementation](https://github.com/sqliteai/sqlite-vector/blob/1.2.0/src/sqlite-vector.c#L2692-L2945))

FTS5/utf8proc can address concrete ASCII-limited `recall_terms.c` behavior, but full-text changes require **reach evaluation**, not a claim that a new index fixes understanding. FTS5 Unicode61 uses Unicode 6.1; trigram queries have short-pattern limits; MariaDB-equivalent matching is not automatic. Measure exact-neighbor agreement separately from answer-bearing-source recall and faithful use. Raw FLOAT32 storage is `N × 1024 × 4` bytes—arithmetic only, excluding IDs, graphs, caches, allocator and process overhead. Index replacement changes neither embedding nor BF16 reranking/generation allocations. Keep Qdrant if model time dominates and measured whole-system savings do not justify replacement recovery code. ([FTS5 tokenizers](https://sqlite.org/fts5.html#tokenizers), [Retrieval experiment design](../research_notes/Lightweight%20components%20for%20Scribodo/retrieval-indexing.md))

## Retain inference policy and borrow literary knowledge conservatively

**Maintain llama.cpp rather than changing inference ecosystems.** The current pin `5851a8e505f4` matches two independently checked advisories: **CVE-2026-133710**, crafted `hrm_text` GGUF overflow/heap overwrite, fix `50518b64c6f2191a116d2760042f106c4b3387d7` (`b12556`); and **CVE-2026-134540**, invalid `grammar_triggers[].type`, fix `9f26fe11c73c7e74a5e99e7f1b6370ad8e1cb22d` (`b12405`). Pinned model hashes/private authenticated sockets limit exposure but do not establish non-reachability. Select a reviewed pin with verified ancestry containing both fixes, or reviewed backports; neither observed HEAD nor “latest release” was established as a shipping-safe choice. Preserve official unquantized BF16 weights, `-fa off -ctk bf16 -ctv bf16 --jinja`, tokenizer/template controls and BF16/F32 execution gates. This is mandatory policy, not a knob to relax for reuse. ([Loader advisory](https://api.osv.dev/v1/vulns/CVE-2026-133710), [Grammar advisory](https://api.osv.dev/v1/vulns/CVE-2026-134540), [Audit](../docs/AUDIT-005-repository-audit.md), [Runtime validation](../docs/MODEL-001-lfm3-runtime.md))

`server.c` already provides model validation, private sockets, authentication, bounded startup, restart backoff and orphan handling; keep it with `generative_gate.c` and `memfit.c`. Keep the Qwen reranker adapter unless the upstream rerank endpoint proves prompt, score, token, ranking and precision parity. Trial libcurl inside the unchanged `http.h` contract rather than adding another HTTP dependency: `remote.c` already uses it. Curl can remove maintained framing/socket code, but SSE assembly, caps and authorization remain. Its idle progress callback can be roughly one-second cadence, unlike current 100 ms polling slices; a bounded multi-handle loop must preserve cancellation and absolute deadlines. Keep local endpoint admission, auth, allocation bounds, streaming errors, redirect/proxy rules and **no automatic fallback in either direction**. No net code saving or latency improvement has been measured. ([Inference source analysis](../research_notes/Lightweight%20components%20for%20Scribodo/inference-verification.md), [Curl progress semantics](https://curl.se/libcurl/c/CURLOPT_XFERINFOFUNCTION.html))

Existing schema-constrained extraction in `answer_pipeline.c` already buys syntactic structure. JSON schema cannot establish source entailment, consent or correct interpretation; truncation still occurs. Do not add llguidance/XGrammar/Outlines for fashion. [llguidance](https://github.com/guidance-ai/llguidance/tree/4b1bdd7eaab212dacdbcebcd71ad84d194dfc629) is a conditional server-side trial only for demonstrated grammar coverage/performance need: inspected manifest 1.9.1, MIT Rust core, but llama.cpp's inspected optional integration pins a different revision labeled v1.0.1. Test the actual combination; initial product-code removal is essentially none. [LLVM libFuzzer](https://llvm.org/docs/LibFuzzer.html) is the stronger low-footprint addition: development-only ASan/UBSan fuzzing of HTTP decoding, extraction/claim parsers, span normalization and receipt round-trips, retaining deterministic semantic oracles and allocation-fault tests. It is maintained for important fixes, not major feature development. Optional [Mull 0.39.1](https://github.com/mull-project/mull/releases/tag/0.39.1), Apache-2.0, must justify LLVM/plugin upkeep and supplement—not replace—domain-specific authorization mutations. ([Inference/testing comparison](../research_notes/Lightweight%20components%20for%20Scribodo/inference-verification.md))

**No proven lightweight comprehensive observer drop-in emerged.** `observer_model.c` already shares the existing generator for bounded entity/event/relation/question extraction and judgment; `observer_job.c` tracks source pieces and fences. Improve `store_entities.c` first with utf8proc-derived keys and a reversible mention ledger: stable entity IDs, exact source spans, observed names, author-approved aliases and ambiguous candidate resolutions. Replace destructive first-name folding with revisable proposals rather than a new graph database. Borrow bounded title/name-variant indexing and literary failure fixtures from [BookNLP](https://github.com/booknlp/booknlp/tree/3d900fc2224e55960c3363826ae28539b77b4204), inspected July 12, 2024, manifest **1.0.7**, MIT code. Its own warning that full-book coreference conflates entities supports abstention. Do not import Python/torch/spaCy/transformers or assume MIT clears downloaded weights, nickname assets or LitBank fixtures. ([BookNLP name algorithm](https://github.com/booknlp/booknlp/blob/3d900fc2224e55960c3363826ae28539b77b4204/booknlp/english/name_coref.py), [Coreference limitations](https://github.com/booknlp/booknlp/blob/3d900fc2224e55960c3363826ae28539b77b4204/README.md#character-name-clustering-and-coreference), [Observer analysis](../research_notes/Lightweight%20components%20for%20Scribodo/observer-knowledge.md))

[GLiNER.cpp](https://github.com/Knowledgator/GLiNER.cpp/tree/af99d2b1fddbfde644e07b159730a76f876ae517), inspected July 10, project **0.0.2**, Apache-2.0 code, is only a bounded optional NER prototype. It adds C++, ONNX Runtime, Rust tokenization, PCRE2 and documented OpenMP; no stable C ABI or macOS arm64 validation was established. Separately, [gliner_small-v2.1 weights](https://huggingface.co/urchade/gliner_small-v2.1/blob/4e091416cf7c3481db542c2a3d26156916f3a47f/README.md), revision `4e091416…`, are Apache-2.0; older NC weights are not substitutes. At 166M parameters, FP32 weights alone imply about 664 MB decimal—**not measured runtime memory**. It is a fourth model, not a free C replacement or proven contradiction engine. Emit original-byte span proposals before canon pairing; keep event/question extraction and judgment initially. Classifier precision requires its own policy review; it must not be confused with or relax the mandatory BF16 policy for any added generative model. ([Native build](https://github.com/Knowledgator/GLiNER.cpp/blob/af99d2b1fddbfde644e07b159730a76f876ae517/CMakeLists.txt), [Observer deployment gaps](../research_notes/Lightweight%20components%20for%20Scribodo/observer-knowledge.md))

Graphiti's source/support and temporal fields are useful design references, not deployment recommendations. Keep assertion time, story time and author approval separate; “later ingested” is not “truer.” Existing finding-backed links already form a provenance graph. Do not install Graphiti/Mem0/LightRAG to automatically promote or invalidate generated facts: that violates author-only canon even when providers are local. Likewise, exact-span verification proves occurrence, **not correct interpretation**. The repository-reported historical default observer scores—7/20 planted recall and 7/92 conflict precision—were not rerun; gated 9/12 recorded-reply co-signer precision is not a new live default. No library here has demonstrated an improvement to those results. Retrieval reach and faithful use remain distinct; post-stream bounded claim checks are not proof that every displayed answer is true. ## Stage adoption so failed experiments leave a smaller system

**Stage one is correctness and baseline measurement, not migration.** Subject to separate implementation authorization, reproduce and fix F1–F3 in callers, triage both runtime advisories and the image digest, then establish current whole-app/process memory, UI stalls, startup, backup/recovery, retrieval reach and observer quality. Add one or two pure libFuzzer targets. Retain current diff: `diff.c` already bounds Myers-style work and falls back to whole replacement; improve Unicode token boundaries before replacing it. Its exact-anchor acceptance controller is more important than which algorithm draws the diff. Precommit cost/latency thresholds using existing product budgets rather than inventing savings after results. ([Audit regression gates](../docs/AUDIT-005-repository-audit.md), [Diff inspection](../research_notes/Lightweight%20components%20for%20Scribodo/native-authoring.md))

**Stage two is bounded, independently killable experiments.** Compare the native text island against current editing using identical manuscripts: IME marked-text commit/cancel/reconversion, dead keys, emoji/combining/Indic/bidi navigation, VoiceOver, focus, undo across accepted edits, dirty/save/recovery and long-document latency. Kill it if anchors, original bytes, undo or focus cannot be preserved at acceptable cost; do not convert the whole UI to rescue the experiment. Separately test utf8proc keys with collision-aware aliases and no irreversible merges, and libcurl under fragmented SSE, malformed bodies, idle cancellation, hard deadlines, auth and allocation/cap failures. Kill transport consolidation if maintained code does not shrink or policy/tail latency regresses. ([Native acceptance corpus](../research_notes/Lightweight%20components%20for%20Scribodo/native-authoring.md), [Transport gates](../research_notes/Lightweight%20components%20for%20Scribodo/inference-verification.md))

**Stage three chooses retrieval scale before choosing ANN.** Freeze original sources, scope snapshots, embedding/model/chunker hashes, metrics and current fusion/reranking. Compare Qdrant production and exact, eligible-array exact and sqlite-vec release exact; test lexical changes independently. Include stale generations, revoked chats, detached/changed saved files, old revisions, corrupt checkpoints, churn and death around index success/outbox acknowledgement. Any unauthorized or stale source admitted to a packet is disqualifying. Require no held-out reach regression within existing preparation budgets; measure index-only, embedding, reranking, generation and whole-process costs separately. Escalate to released USearch only if exact exceeds preregistered budgets and ANN meets them without unacceptable reach loss. Kill embedded replacement if Qdrant overhead is immaterial or equivalent recovery code outweighs savings. ([Retrieval preregistration](../research_notes/Lightweight%20components%20for%20Scribodo/retrieval-indexing.md))

**Stage four decides the optional embedded authority migration.** Import a consistent MariaDB export into a separate SQLite prototype and compare every original byte/hash, project/document/revision ID, sequence, saved pointer, source range, author status, consent flag, tombstone and pending job. Exercise long/sanitization-colliding filenames, copy versus move, schema refusal, paused authority and restart before/after SQL commit, file rename, marker publication and index acknowledgement. Stress simultaneous chat, observer, import, Recall and online backup with disk-full, permission/I/O errors and stale leases. Require bounded UI work, no silent loss/duplicate append/cross-document resolution, no unbounded WAL or job starvation under intended concurrency. Retain the original database/export until independent restore succeeds. Kill migration if single-writer contention defeats liveness or if legacy/MariaDB/SQLite must remain permanent competing histories; lower service count alone is not success. ([Storage parity and durability gates](../research_notes/Lightweight%20components%20for%20Scribodo/storage-recovery.md))

**Stage five earns observer additions through ablation.** Hold the BF16 generator, prompts, canon and judge budget fixed; compare current extraction, Unicode-only keys, reversible aliases/mention ledger, then optional native NER. Use fresh legally usable novels with ambiguous names, pronouns, quoted/hypothetical claims, changed facts and obsolete sources. Measure false merges, abstention, canon-pair reach and end-to-end conflict recall/precision separately, with per-book uncertainty and foreground/backlog costs. Apply repository quality gates rather than upstream NER F1. Reject the fourth model if cheap deterministic changes perform equivalently; any automatic canon mutation, source mismatch, scope leak or silent cloud fallback fails regardless of score. ([Observer ablations and gates](../research_notes/Lightweight%20components%20for%20Scribodo/observer-knowledge.md))

Every promoted component needs an **offline Apple Silicon deployment/device-cleanroom gate**: pinned source and generated data, actual linked dependencies, code/data/model licenses separately, model hashes and execution precision, packaged helper discovery, signing where applicable, clean-machine launch/restore and denied-network behavior. Existing generative and reranker model redistribution/commercial terms were not cleared by these notes; MIT llama.cpp does not clear weights. Test backups from an external disk without the original machine, including credentials/keys and corruption disclosure. Only remove old production paths after supported migration and rollback evidence; a research recommendation is not authorization to implement.

## Conclusion

**Choose the minimal-change track now; make the embedded target earn adoption.** The strongest composition is not the most comprehensive package: it is the smallest set of mature mechanisms that lets Scribodo delete responsibilities without surrendering its author contract. SQLite deserves the largest architectural experiment; AppKit deserves the focused editing experiment; exact search deserves measurement before ANN. Unicode utilities and dev-only fuzzing offer narrow reuse without another service or model. Preserve custom authority/routing, scope/admission, anchors, provenance, receipts and measured gates because those are the workbench—not incidental plumbing.

The ranking remains conditional on evidence not yet collected: no direct empirical candidate comparison, current arm64 build, complete transitive SBOM/license closure, model-license clearance or new author-pilot run was performed. GitHub rate/anti-abuse limits left several release, issue-health and secondary license lookups incomplete; checked HEADs, manifest versions and latest-release API selections must not be conflated. Upstream facts establish plausible integration paths, not measured savings, security clearance or improved fiction understanding. The decisive next choice is whether a bounded prototype **removes more system than it adds while preserving every source and authority invariant**; if it does not, keeping the existing tailored implementation is the efficient outcome.
